# base_d: 차량 거점 쉼터·요리·인사 훈련 에셋 명세

이슈 [#66](https://github.com/Allo-MJU/allo/issues/66) (상위 [#58](https://github.com/Allo-MJU/allo/issues/58)) · D 박찬 작성

> **상태: 시안 명세.** 쉼터·요리·인사 훈련과 모든 수치는 팀이 제안한 MVP이며 승인된 제품 규칙이 아니다. 역할 캐릭터 배정과 활동 규칙은 C와 팀이 정하고, 아트가 역할표를 확정하지 않는다. 기준은 디자인 시스템 [PR #48](https://github.com/Allo-MJU/allo/pull/48)의 12종과 와이어프레임 [PR #49](https://github.com/Allo-MJU/allo/pull/49)다. 두 PR은 아직 OPEN이다.

## 범위

- 폰에서 확인하는 차량 거점의 세 영역(건설·요리·훈련)과 활동 결과를 나타내는 배경, 오브젝트, 캐릭터 연출.
- 제안 첫 활동: 건설 영역의 쉼터, 요리 영역의 식탁/메뉴(최대 2종), 훈련 영역의 인사 동작.
- 제외: 신규 종, 경제 아이템·재료·보상 수치, 3D 자산. 기존 12종 외형은 바꾸지 않고 기존 자산을 먼저 재사용한다.

## 미결정 항목

| 항목 | 내용 | 처리 |
| --- | --- | --- |
| D08 | 폰 조작 범위, 세 역할의 종 매핑, 활동 구성·시간 | 종 자리는 `{id}`로 비워 둔다. 역할표를 만들지 않는다 |
| D10/D11 | 저장·호환 | 상태 이름만 제안하고 저장 값은 C가 정한다 |

## 상태표

세 영역(`build`, `cook`, `train`) 모두 같은 상태를 가진다.

| 상태 | 표현 | 비고 |
| --- | --- | --- |
| `locked` | 잠긴 영역 | 잠긴 이유를 글로 함께 보여준다. 그림만으로 이유를 말하지 않는다 |
| `open` | 열린 영역 | 활동 시작 전 |
| `placed` | 역할 캐릭터가 자리에 선 상태 | 캐릭터 배정은 C 결정 |
| `working` | 작업 중 | 진행 정도를 나타내는 장면 하나면 충분하다 |
| `done` | 결과 완료 | 쉼터 배치 / 메뉴 1~2종 / 인사 동작 결과 |
| `retry` | 취소 뒤 다시 들어온 상태 | 완료로 오해하지 않게 `open`과 구분 |
| `static` | 미지원·누락 폴백 | 잠금·완료 상태를 오해하지 않는 정적 이미지 |
