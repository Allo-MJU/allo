# 바다 탐험 테스트 화면

Android `ALLO_API_36` 에뮬레이터에서 직접 눌러보는 폰 앱 파일럿이다. 가상 주행을 사용하므로 실제 차량, Firebase 설정, API 키 없이 실행한다.

## 다시 열기

저장소 루트에서 실행한다.

```bash
scripts/demo_sea_learning.sh
```

현재 빌드된 APK를 앱 데이터 유지 방식으로 설치하고 실행한다. 에뮬레이터가 닫혀 있으면 `ALLO_API_36`을 시작한다. 여러 에뮬레이터 중 하나를 지정하려면 `ALLO_SEA_DEVICE=emulator-5554 scripts/demo_sea_learning.sh`를 사용한다.

소스를 수정한 뒤에는 `scripts/demo_sea_learning.sh --build`로 Unity 내보내기부터 다시 빌드한다. 기본 Unity 경로는 `6000.0.85f2`다.

## 화면에서 해보기

1. 오른쪽 **차 안** → 위쪽 **차량 QR 연결하기** → **테스트 연결**.
2. 오른쪽 아래 **탐험 노트** → **상상 탐험 · 바닷바람 우편배**.
3. **다음** → **돛 펼친 배 / 돛 접은 배** 중 예상 선택.
4. 먼저 해볼 조작을 고르고 **비교해 보기 → 돛 바꾸기 → 발견 보기 → 왜 그럴까?**로 진행.
5. 이유를 읽고 여행을 마친 뒤 **발견 카드 담기**.
6. **돌아가기** 후 노트의 **발견 · 바닷바람 우편배**를 눌러 내 예상·첫 조작·비교 결과·원리를 다시 확인.

이미 카드가 있으면 카드를 연 뒤 **다시 실험하기**를 누른다. 진행 중인 탐험이 복원되어 재실험 버튼이 비활성화되면 노트에서 **이어 하기** 또는 **탐험 마치기**를 먼저 선택한다. 뒤로 가기나 **돌봄으로**는 진행을 보관하고 차 안으로 돌아간다.

초기 실행은 Unity가 열릴 때까지 잠깐 기다린 뒤 조작한다. 데모 확인 과정에서 저장한 샘플 카드가 있으며, 실제 아이의 학습 성과 기록을 뜻하지 않는다.

## 확인한 범위

- 예상 선택부터 두 조건 비교·설명·저장까지 Android 화면에서 직접 진행했다.
- 최종 APK 업데이트와 앱 재시작 후 개인 카드가 복원되는 것을 확인했다.
- 2400×1080 및 800×360 가로 화면을 확인했다. 작은 화면 확인 때 변경한 해상도·글자 크기·야간 모드는 원래대로 복원했다.
- 이 파일럿은 폰 앱에 적용했다. Pleos 차량 앱 연결과 실제 차량 검증은 후속이다. 새 문장 일부는 자막으로 제공하며 실제 기기 음성 품질은 검증하지 않았다.
