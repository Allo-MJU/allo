# ALLO 폰 앱 디자인 시스템 V2 (초안)

폰 앱(가로 812×375 논리 px)의 시각 토큰, 공통 컴포넌트, 상태 표현 규칙을 정리한다. 구조와 상태 규칙은 이슈 #92의 차량 화면 설계를 기준으로 삼고, 시각 스킨은 폰의 3D 장난감 스타일을 유지한다. 값은 `docs/mockups/v2/allo-flow.html`의 실제 CSS에서 가져왔다. 이 문서는 제안이며 팀 확정안이 아니다.

## 1. 차량 화면과의 관계

| 항목 | 차량(#92) | 폰(이 문서) | 공유 여부 |
|---|---|---|---|
| 화면 구조 | 헤더 + 주 콘텐츠(왼쪽 캐릭터, 오른쪽 정보·행동) + 하단 상태 띠 | 같음 | 공유 |
| 상태 어휘 | 정상, 확인 중, 실패, 끊김, 종료 | 같음 | 공유 |
| 화면 우선순위 | 주행·UX 제한 > 세션 종료 > 연결 끊김 > 폰의 확정 상태 | 세션 종료 > 연결 끊김 > 확정 상태(주행 제한 없음) | 일부 |
| 원칙 | 확인되기 전에는 성공으로 표시하지 않는다 | 같음 | 공유 |
| 문구 | 존댓말, 무슨 일이 일어났는지와 다음 행동 | 같음 | 공유 |
| 시각 | 어두운 평면, 노랑 강조(`#FCCC44`) | 크림·민트 3D 장난감 | 공유하지 않음 |
| 글꼴 | Apple SD Gothic Neo 시안, Pleos 글꼴 검토 | Do Hyeon + Noto Sans KR | 공유하지 않음 |

폰은 운전자가 보는 화면이 아니므로 주행 제한 화면은 없다. 대신 차량의 주행 제한이 걸린 동안 폰에서 차량 조작이 필요한 행동(친구 보내기 등)은 비활성으로 표시한다(미구현, 계약 확정 후).

## 2. 토큰

### 색

| 이름 | 값 | 면 아래 | 하이라이트 | 용도 |
|---|---|---|---|---|
| 먹(텍스트·테두리) `--N` | `#5C4B51` | | | 글자, 3.5px 테두리 |
| 크림 `--cream` | `#FBF3DD` | `#D9C9A0` | `#FFFFFF` | 기본 버튼, 패널 |
| 민트 `--g` | `#86D6AE` | `#5DB38A` | `#BDEBD3` | 일반 행동, 정상 |
| 하늘 `--b` | `#8CCBF2` | `#5EA7D6` | `#C2E6FB` | 보조 행동, 대기 |
| 노랑 `--y` | `#FFD966` | `#E0AE3A` | `#FFEBA8` | 이 화면의 주요 행동 하나 |
| 회색 `--gy` | `#9AA0CC` | `#6F76A6` | `#C8CCE8` | 준비 중, 종료, 예약 슬롯 |
| 산호 `--r` (신규) | `#F4A59B` | `#D27C72` | `#FBD0CA` | 실패, 끊김, 거절 |

상태 띠 배경: 정보 크림, 대기 `#DDF1FD`, 오류 `#FDE3DF`. 패널 배경은 대기 `#F1F9FE`, 오류 `#FFF1EE`로 살짝 물들인다.

규칙: 노랑은 한 화면에 주요 행동 하나에만 쓴다. 상태는 색만으로 구분하지 않고 아이콘(i, …, !)과 글자를 함께 쓴다.

### 글자

| 역할 | 글꼴 | 크기 | 비고 |
|---|---|---|---|
| 화면 제목(헤더 알약) | Do Hyeon | 22 | |
| 패널 제목 | Do Hyeon | 26~28 | 한 줄 |
| 버튼 | Do Hyeon | 17~19 | |
| 본문 | Noto Sans KR 500 | 14~15 | `word-break:keep-all` |
| 보조·캡션 | Noto Sans KR 500 | 12~13 | 칩, 안내 상자 |

차량 시안의 보조 글자 18sp 기준에 비하면 폰의 보조 글자가 작다. 폰은 손에 쥐고 보는 거리라 허용하되, 실기 확인이 필요하다.

### 간격과 모양

- 안전 여백: 좌우 27, 위 15(헤더)~21(버튼), 아래 21. 패널은 좌우 24.
- 모서리: 버튼과 칩은 알약(99), 정사각 버튼은 22, 패널은 26.
- 테두리 3.5px 먹색. 밑면 6px 단색(면 아래 색) + 부드러운 그림자. 누르면 4px 내려앉고 97%로 줄어든다.
- 장면 위에서는 배경을 흐리게(블러 6px) 하고 위아래로 어둡게 깔아 패널과 글자의 대비를 확보한다.

## 4. 상태 표현

| 상태 | 칩 | 패널 | 띠 | 버튼 | 캐릭터 |
|---|---|---|---|---|---|
| 정상 | 연결됨(초록 점) | 기본 | 정보(i) | 노랑 주요 | 선택된 포즈 |
| 확인 중 | 하늘, 깜빡임 | 하늘 기운 | 대기(…) | 비활성, "확인 중" | 정지 |
| 실패 | 산호 | 분홍 기운 | 오류(!) | 노랑 "다시 시도" + 돌아가기 | 마지막 확인 모습 + 캡션 |
| 끊김 | 산호 | 분홍 기운 | 오류(!) | 노랑 "다시 연결하기" | 마지막 받은 모습 + 캡션 |
| 거절 | 산호 | 분홍 기운 | 오류(!) | 보조 "광장으로" | 마지막 확인 모습 + 캡션 |
| 종료 | 회색 | 기본 | 정보(i) | 노랑 "다음 연결 준비" | 잠자는 포즈 |

규칙
1. 확인되기 전에는 성공으로 표시하지 않는다. 응답이 늦어도 실패로 단정하지 않는다("확인 중" 유지).
2. 실패 화면은 무엇이 바뀌지 않았는지를 먼저 말한다("기존 친구는 그대로예요").
3. 마지막으로 확인한 상태를 보여 줄 때는 캡션 칩으로 표시한다.
4. 자동 재시도·자동 재개를 하지 않는다. 다시 하려면 사용자가 누른다.
5. 이전 세션이나 이전 개체의 늦은 응답은 현재 화면에 적용하지 않는다.

│  [캐릭터 무대 290×226]   [상태 패널 left 362~]    │  y 62~294

## 7. 한계와 열린 항목

- 차량 시안의 문구와 상태 이름은 이슈 코멘트(v3~v6)에서 읽은 것이고, 일부 코멘트 본문은 도구가 압축해 전부 읽지 못했다.
- 폰 상태 화면의 동작은 이슈의 제안을 따른 가안이다. 계약(#54, #60, #72)이 확정되지 않았다.
- 새 화면의 문구 일부(예: "차를 세웠다고 저절로 끝나지는 않아요")는 차량 설계의 규칙을 폰 입장으로 옮긴 것이다. 차량 작성자와 확인이 필요하다.
- 스크린샷은 정지 화면이다. 연출 중간 상태, 실기 시인성, 글꼴 배율은 확인하지 않았다.
- 폰 팔레트(크림·민트·코코아), 차량 팔레트(먹색·`#FCCC44`), dev의 확정 가이드가 서로 다르다. 폰이 차량과 맞출지는 결정이 필요하다.
- 상태 아이콘(i, …, !)은 시안에서 코드 글자로 대체했다. 제작본은 `docs/asset-request.md` 3-4에 요청해 두었다.
