# 교육 대화 실제 AI 확인: 이 작업 공간의 실행 순서

2026-11-14 · 차량 연결·독립 알 돌보기·서버 직접 대화 통합본.

## 먼저 끝낸 작업

- 기존 기능 브랜치와 마을 UI를 통합하고 빈 차량 → 연결/QR → 알 준비 흐름을 적용.
- 상단 `차량 QR 연결하기`에서 연결 화면에 들어간다. 왼쪽 원형 간식·물·공·인형을 고르면 하단에 물건이 나타나며 위·좌우·대각선으로 밀어 던진다. 아래로 당기는 동작은 취소한다. 알과 친구는 독립적으로 진행한다.
- 캐릭터는 한 번 탭으로 대화, 문지르기로 쓰다듬기, 더블 탭 후 끌기로 원하는 자리에 옮긴다. 쿠션·담요에 놓으면 해당 반응이 실행된다.
- 캐릭터 12종의 고정 스토리 12편·36장면과 기존 부화 종 6종의 서버 대화 프로필. 신규 스토리 11편과 기존 종 프로필은 사람 검토 전 초안.
- 로컬 Python 실행 환경과 에뮬레이터 연결 설정 준비. OpenAI API 키는 저장하지 않았음.
- 실제 앱→Python HTTP 검증의 AI 응답은 대체 응답. 실제 모델 검증과 구분.

## 키 없이 연결/QR 화면 먼저 확인

새 차 안 화면은 연결 버튼에서 시작한다. 연결/QR 진입·직접 입력·알 준비·친구 소환과 오류 UI는 키 없이 확인할 수 있다. 구버전 작성형 API는 남지만 새 캐릭터 대화는 서버 AI의 greet/chat을 사용한다.

```bash
server/affinity/.venv/bin/python scripts/run_learning_demo.py --without-ai
```

이 모드에서 새 캐릭터를 클릭하면 AI 키 미설정에 따른 대화 연결 오류를 정직하게 표시한다. 앱이 로컬 이야기나 페르소나로 응답을 대신 만들지 않는다. 실제 AI 확인은 아래 단계에서 키를 입력해 서버를 다시 켠다.

## 1. API 키 만들기

[OpenAI API 키 관리](https://platform.openai.com/api-keys)에서 로그인 후 새 키를 만든다. 키는 채팅으로 보내지 않는다. 공식 안내는 [API 키 생성 및 환경 변수](https://developers.openai.com/api/docs/quickstart#create-and-export-an-api-key)를 참고한다.

키 생성 후에는 아래 서버 실행 터미널에 직접 입력한다. 이 작업에서는 키를 셸 명령이나 파일에 적을 필요가 없다.

## 2. 로컬 서버 켜기

Mac 터미널에서:

```bash
cd /Users/seokamoto/.codex/worktrees/companion-learning-latest/allo
server/affinity/.venv/bin/python scripts/run_learning_demo.py
```

`OpenAI API key (hidden, not saved):`가 나오면 키를 붙여넣고 Enter를 누른다. 붙여넣은 글자가 표시되지 않는 것이 정상이다. 키는 실행 중인 서버 프로세스에서만 사용한다.

`Starting emulator API on 127.0.0.1:8787`가 나오면 터미널을 열어 둔다. 종료는 Ctrl+C다. 이 메시지는 서버 시작 안내이며, 실제 모델 응답 성공을 의미하지는 않는다.

기존 `OPENAI_API_KEY`가 해당 터미널 환경에 이미 설정되어 있으면 입력을 생략한다. `--check`는 비공개 로컬 설정 형식만 검사하며 모델을 호출하지 않는다.

## 3. 에뮬레이터 앱에서 확인

이번 debug APK는 Android 에뮬레이터의 `10.0.2.2:8787`로 Mac의 로컬 서버에 연결하도록 빌드한다. 실제 폰이나 원격 서비스용 주소가 아니다. 앱과 서버는 같은 비공개 로컬 데모 설정을 사용한다.

차 안의 차량 연결하기 → 차량 QR 또는 직접 입력 → 성공 후 알 확인 → 친구/도감의 길싹이 → 차 안으로 데리고 오기 → 실제 캐릭터 클릭 → 바로 대화 순서로 확인한다. 이야기 듣기/말 걸기 메뉴나 다음 이야기 버튼은 사용하지 않는다. 예시 질문은 “씨앗이 자라려면 무엇이 필요해?”다. ‘미리 준비한 이야기’나 연결 실패 안내가 아닌 생성 답변이 왔는지 구분한다.

## 4. 이어서 확인할 내용

서버를 켰다고 알려주면 실제 제공자 응답, 같은 친구와의 후속 질문, 고정 사건 유지, 영어 단어와 가끔 나오는 부모님 제안, 음소거·중단을 순서대로 검증한다. 실제 모델 품질과 한국어·영어 TTS 발음은 자동 단위 테스트 통과만으로 완료 처리하지 않는다.

## 5. 실제 폰·원격 서버는 이후

현재 준비는 Mac+Android 에뮬레이터용이다. 실제 폰에서 사용할 때는 접근 가능한 HTTPS 서버 주소와 인증 설정을 정하고 그 주소로 앱을 다시 빌드해야 한다. 원격 배포 대상은 아직 정하지 않았으며 원격 인프라를 새로 만들지 않았다.
