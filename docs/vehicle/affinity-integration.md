# 호감도 부화와 차량 화면 연결

기준: 차량 PR #91 `c7b9fe9`, 호감도 PR #93 `487cb7b949a87604c9b8b020c7fed3910b554252`. PR 병합 없이 필요한 폰 로직과 차량 계약을 로컬 작업에 통합한다. Firebase 배포·실기 통합은 별도 대기다.

## 확인한 계약 차이

| 항목 | #91 | #93 | 통합 원칙 |
| --- | --- | --- | --- |
| 호감도 | score/target/ready 기반 차량 파서 | 소수 score/target/phase/photoCompleted | 새 단계 해석 추가, 기존 ready 형식 호환 |
| 상태 순서 | contractVersion 2 + gameRevision 필수 | contractVersion만 발행 | 폰의 단일 발행 경로에서 전체 snapshot revision 증가 |
| 게임 발행 | 낚시·동행·이동 결과 함께 발행 | 알/호감도 중심 | 기존 fishing/companion/transferResult 보존 |
| 부화 준비 | ready와 성공 구분 | 50점 사진 잠금, 완료 뒤 100점 즉시 부화 | 사진·저장 대기와 저장된 성공을 구분 |

## 화면과 판정 책임

폰이 점수·사진 완료·마감·부화 결과와 도감 저장을 판정한다. 차량은 받은 요약만 표시하며 점수 적립, 사진 완료, 성공을 자체 추정하지 않는다.

| affinity.phase | 차량 의미 |
| --- | --- |
| incubating | 호감도 쌓는 중. 시간/거리 진행률과 별개 |
| photoRequired | 폰에서 사진 퀘스트 확인 |
| resultPending | 폰의 부화 결과 저장 대기. 성공 연출 금지 |
| hatched | 저장된 부화 결과 |
| failed | 부화 실패 |
| discarded | 이번 알 종료 |

부화한 새 알의 speciesId와 이미 선택한 동행 개체는 서로 다른 정보다. 낚시 중에도 호감도 상태를 함께 받을 수 있고, 알의 성공·실패가 기존 동행 선택이나 낚시 보상을 초기화하지 않는다. 사진·발화 원문·사진 ID·API 토큰은 차량 snapshot에 포함하지 않는다.

## 실행 범위

새 호감도는 `startIncubating(tier, useAffinity: true)` 명시 호출로 활성화한다. 기존 시간 기반 모드는 유지한다. 아래 일반 폰 입력 화면 후속에서 별도의 호감도 시작 옵션을 제공한다. 실제 카메라·STT·3D 입력 및 사진 서버 배포를 추가한 작업은 아니다. #93의 기존 호감도 규칙을 사용하며 이번 연결을 위해 규칙을 바꾸지 않는다.

로컬 검증은 합성 API 결과와 제어된 시간으로 폰 컨트롤러가 발행한 상태를 차량 파서·표현에 연결하는 방식이다. 실제 모델 품질·카메라·Firebase 왕복·Pleos 주행 허용 여부를 검증한 것으로 보지 않는다.

원래 규칙: [PR #93 기준 문서](https://github.com/Allo-MJU/allo/blob/487cb7b949a87604c9b8b020c7fed3910b554252/docs/affinity-hatching.md).

## 공유 검증 데이터

`data/fixtures/affinity-fishing-v2.json`은 실제 폰 `GameController` 시나리오가 발행한 JSON을 기준으로 한다. 생성 ID·전송 시각·revision만 비교 가능한 값으로 정규화한다. 첫 여행에서 낚시 관찰 기록 1건을 저장하고 낚시를 일시 정지한 뒤, 사진 퀘스트와 부화 저장 실패·재시도를 검증한다. 같은 여행에서 30분을 더 주행해도 알이 추가되지 않는다. 두 번째 여행에서는 새 알을 버리고 세 번째 여행에서는 기한 만료로 실패한다. 세 여행의 스냅샷에서 선택한 친구와 낚시 누적 기록을 유지하며, 재페어링 때 차량 표시 세대와 낚시 lease를 갱신하는지 확인한다.

폰 `affinity_fishing_contract_test.dart`는 실제 serializer 출력과 공유 데이터를 비교하고 차량 테스트는 같은 파일을 읽어 파싱·표시 의미를 검증한다. fixture 갱신은 `UPDATE_AFFINITY_FIXTURE=1`을 명시한 폰 테스트 실행에서만 수행한다.

통합 검토에서 알 실패/버리기 후 전체 game heartbeat가 중단되는 문제를 발견했다. 알이 종료되어도 비최종 차량 신호에 대한 heartbeat를 유지하도록 수정했으며, 6초 후 revision이 계속 증가하는 회귀 검증을 추가했다.

## 일반 폰 입력 화면 (2026-11-12 후속)

일반 연결 화면에 기존 시간 기반 품기와 별도의 호감도 시작 옵션을 제공한다. 호감도 화면은 전체 화면 설정에서도 입력 패널을 표시한다. 쓰다듬기·4구역 배치·텍스트 말 걸기는 컨트롤러 API를 사용하며, UI가 점수나 쿨다운을 별도로 판정하지 않는다. 사진 퀘스트는 50점 잠금·확인 중·완료 상태와 서버 결과 재확인을 표시한다.

말 걸기는 현재 텍스트 입력이며 STT가 아니다. 일반 앱의 말 판정/사진 결과 재확인은 `ALLO_DEMO_API_URL`과 `ALLO_DEMO_TOKEN`이 유효하게 설정된 API를 사용한다. 설정이 없으면 서버 입력을 사용할 수 없다고 안내하며 합성 성공으로 대체하지 않는다. 카메라 촬영·알 합성·실제 사진 업로드 화면 및 아동용 자유대화 가드레일 통합은 별도 범위다.

Firebase 없이 일반 화면을 재현하는 명시적 debug 진입점:

```sh
# phone 폴더에서 실행
flutter run -t lib/main_local_affinity.dart -d <android-device-id>
```

이 진입점은 실제 일반 AlloApp 화면과 GameController를 사용하고, 메모리 전용 도감·낚시 저장 및 합성 API를 주입한다. 상단 배너에 Firebase/실차/실제 AI/카메라가 아님을 표시한다. 시간 이동과 모의 사진 완료는 검증 전용이며 생산 화면에 포함되지 않는다. 앱 종료 후 모의 진행은 사라지고 기존 저장 데이터는 수정하지 않는다.

### 일반 입력 화면 검증 결과

- 폰 전체 295개 테스트 통과(기존287 + 일반 입력 UI3 + 로컬 실행환경5). 기존 품기·부화·도감·세션 종료 회귀 테스트 수정 없이 통과.
- 말 걸기 1회 제출/쿨다운, 쓰다듬기/구역 입력, 사진50점 잠금, 서버에 확인된 receipt만65점으로 복구하는 UI 테스트 포함.
