# 목적지 음성 입력 — Pleos SpeechToText

2026-11-15 사용자 결정: 에뮬레이터에서 Gleo 연결이 동작하지 않아 기존 목적지 제안·수락·다음 후보를 SpeechToText SDK로 연결한다. 기능은 proposal.md의 목적지 흐름을 유지한다. Qwen TTS는 유지한다.

## 범위

- 음성 인식은 Pleos SpeechToText 3.3.1 ON_DEVICE / 한국어. ALLO 앱은 외부 STT·원음 수집·발화 원문 저장·로그·Firebase 전송을 하지 않는다. 에뮬레이터의 Pleos 시스템 서비스 자체 로그에는 인식 원문이 출력되는 것을 관찰했다.
- 목적지 추천 요청 → 기존 SessionManager.suggestDestination(). 수락 → 기존 acceptDestination(). 다음 후보 → 현재 제안이 유효할 때 suggestDestination() 재호출.
- 기존 수집 추천과 별도의 travelRequest 부탁 기능을 합치지 않는다. 거절 명령, 자유 대화, 새 추천 알고리즘을 추가하지 않는다.
- Gleo schema/receiver는 호환 경로로 유지한다. 별도 STT 인식 결과만 기존 함수에 연결한다.
- 폰 이야기 스트리밍은 변경하지 않는다. 광장은 후속 승인에 따라 번들 원본 WAV를 사용한다. 목적지 안내는 폰에서 설정한 차량 동행의 기존 Qwen 캐릭터 프로필을 사용한다(2026-11-15 후속 사용자 승인).

## 입력과 수명

기존 정차 ‘여행’ 화면의 음성 요청 시작/중지 제어로 한 회의 인식을 시작한다. 상시 청취·새 호출어 감지·Gleo 또는 시스템 assistant 교체는 하지 않는다. 이 제어는 새 목적지 기능이 아니라 SDK 마이크 세션을 명시적으로 여닫는 입력 수단이다.

추천/다음 후보 안내가 끝난 뒤에만 다음 응답을 듣는다. TTS 중에는 STT를 닫는다. 초기화·한 번의 청취·한 번의 안내에는 각각 20초 상한을 두고, 인식 실패/알 수 없는 문장/오류/시간초과는 종료한다. 자동 반복 재시도하지 않는다.

화면 이탈·백그라운드·주차 확인 해제·연결 종료·세션 교체 시 입력을 취소한다. 현재 화면에서 명시적으로 다시 시작할 때만 마이크를 연다. 중간 인식은 실행하지 않으며 최종 결과의 제한된 명령만 인식한다. 부정·복합·임의 문장은 수락으로 추측하지 않는다.

## 내비 보호

- 수락/다음 후보는 현재 유효한 제안이 있어야 한다.
- 음성 대화 시작 시 세션과 제안 revision을 기억하고, 이 대화가 직접 만든 제안의 revision만 갱신해 응답 시 다시 확인한다. 다른 입력이 새 후보를 만들거나 수집 요약이 바뀌면 이전 음성을 적용하지 않는다.
- 기존 2분 제안 유효시간, 지역 유효성 재검증, Guidance.IDLE 확인, 요청 실패 보호를 유지한다.
- 내비 요청 접수와 실제 안내 시작/방문 완료를 구분한다. 게임 규칙/저장/지역 이벤트 계약을 변경하지 않는다.

## 검증

독립 SDK 진단에서 ON_DEVICE initialize→request→onReady와 stop/release를 확인했다. 실제 발화 인식, 실차 마이크, 음성→내비 전체 흐름은 별도 검증 대상이다. 단위 테스트와 APK 빌드는 실제 음성 성공을 대신하지 않는다.

### 구현 검증 결과

- `JAVA_HOME=<JDK17> ./gradlew testDebugUnitTest assembleDebug`: 성공. 차량 테스트 350개, 실패/오류/건너뜀 0.
- 새 음성 제어 회귀 11개: 정확 구문, 추천→안내→다음 후보→안내→수락, 중복/늦은 콜백, 취소·재시작, 초기화/청취/안내 시간초과, 오류, 허용 상태 변경.
- 추천기 회귀 2개 추가: 같은 장소 재제안도 revision 변경, 안내 실패 시 재시도 가능·후보 교체/소비 시 이전 인식 무효화.
- 독립 검토에서 안내 중 후보 교체를 발견해 수정했다. 다음 인식을 만들 때 현재 후보를 새로 캡처하지 않고, 실제 읽어 준 후보와의 일치를 유지한다.
- SDK 진단 앱은 15초 한 번 실행 후 stop/release·삭제했다. `onReady`까지 확인했으나 인식 결과는 없었으며 실제 발화·내비 통합 성공으로 표현하지 않는다.
- 초기 검증은 SDK 경로만 설정해 수행했다. 이후 기존 Qwen 개발 설정과 로컬 Firebase 모드로 clean 빌드하여 emulator-5554의 사용자 10에 업데이트 설치했다. 인증된 합성 폰 연결은 화면 진입에만 사용했으며 목적지 명령이나 인식 결과는 주입하지 않았다.

### 실제 발화 검증 중 발견한 문제

- 호스트 마이크 활성화 이후 실제 발화의 한국어 최종 결과가 Pleos 서비스에서 생성됐다. 따라서 Mac→에뮬레이터→STT 입력 연결은 확인했다.
- SDK의 `onEndedRecognition()`은 `EPD_OFF`(발화 구간 종료)이며, 최종 결과 `onUpdated(text, true)`보다 먼저 올 수 있다. 이 신호를 실패로 처리한 ALLO 어댑터가 콜백을 먼저 해제해 결과 전달을 잃었다.
- 수정 전에는 목적지 제안·다음 후보·수락·실제 내비 연결 성공을 확인하지 못했다.
- 어댑터가 EPD_OFF 이후에도 최종 결과를 기다리도록 수정했다. 기존 코드에서 회귀 2개 실패를 재현한 뒤 SDK 리스너 테스트 4개와 음성 제어 테스트 11개가 통과했고, 수정 APK 빌드·에뮬레이터 업데이트 설치에 성공했다. 수정 후 실제 음성→내비 흐름을 아래와 같이 검증했다.

### 에뮬레이터 실제 발화 검증 완료

2026-11-15 사용자가 Mac 마이크로 직접 발화했다. 추천·다음 후보·수락 명령이나 STT 결과는 주입하지 않았다.

- 추천 발화: mountain 후보 offered 이벤트 생성, 사용자 음성 안내 확인.
- 다음 후보 발화: coast 후보 offered 이벤트 생성, 사용자 다음 후보 안내 확인.
- 수락 발화: 앱 `accept → Started`, 내비 `GUIDING` / `ROUTE_DRIVE`, ETA 4800초 및 81000m 확인.
- 화면에서 을왕리해수욕장, 1시간 20분·81km, 안내 종료 버튼과 경로 표시 확인. 실제 주행·도착·실차 검증은 수행하지 않았다.

### 여행 화자 연결 (2026-11-15 후속 승인)

여행 목적지 안내는 `companion.speciesId`를 사용한다. 품는 알의 `game.speciesId`나 이야기 탭의 로컬 친구 선택을 화자로 쓰지 않는다(v1의 부화 동행은 기존 legacy 경로 유지). 인식 시작 시 세션·동행 개체·revision·종을 캡처하고 동행 변경·차량 이탈 시 요청과 재생을 취소한다. 유효한 동행이 없으면 임의 기본 캐릭터를 선택하지 않는다.

`/v1/car/destination/clip`은 기존 목적지 템플릿·고정 후보·거리 표현·오류 안내만 받는다. STT 원문이나 원음은 서버로 보내지 않으며, 앱이 선택한 안내 문구와 캐릭터 종만 보낸다. 합성/다운로드 완료가 아니라 재생 완료 뒤 다음 STT를 시작한다. 서버 미설정/실패 시 같은 문장을 Pleos ON_DEVICE TTS로 한 번 대체한다. 대체 재생 완료 뒤에만 다음 STT를 시작하며, Pleos까지 실패하면 텍스트와 오류를 표시한다.

- 차량 전체 테스트 362개, 서버 테스트 28개 통과 및 APK 빌드 성공.
- 실제 Qwen 길싹이·등불나방의 짧은 이야기 대사 합성 200/WAV 확인. 각각 약2.4초/2.3초 음성 생성. 에뮬레이터 재생·선택 화자 검증은 진행 중이다.

### Qwen 실패 시 Pleos 대체 (2026-11-15)

- Qwen 설정 누락, 요청/합성 오류, WAV 재생 오류 또는 다운로드·플레이어 준비가 6초 안에 끝나지 않으면 Qwen 작업을 해제하고 동일 문장을 Pleos TTS로 한 번 재생한다. 성공한 Qwen 재생은 그대로 유지한다.
- Pleos 초기화와 재생에는 합계12초 제한을 둔다. 두 경로가 모두 실패하면 오류를 알리고 텍스트를 유지한다. 여행의 기존20초 전체 안내 제한도 유지한다.
- 중지·화면 이탈·화자 교체·연결 해제는 대체 재생도 해제한다. 이전 Qwen/Pleos 완료 콜백은 새로운 안내나 STT를 시작할 수 없다.
- Pleos 대체 음성은 기본 목소리이며 원본 캐릭터 음색 복제를 의미하지 않는다. Qwen도 등록 복제본이 없어 현재 공용 프리셋을 사용한다. 원본 음색 일치는 미완료다.
