## 현재 계약과의 차이

PR #53 / 이슈 #54의 v2는 아직 합의·병합 전 제안이다. 기존 스키마를 덮어쓰거나 차량이 게임 결과를 판정하지 않는다. `contractVersion: 2`와 비음수 정수 `gameRevision`을 받은 경우에만 새 필드를 읽는다. v2 없는 기존 입력은 기존 표시를 유지한다. 폰이 v2를 쓰지 않으면 아래 기능은 실제 세션에 나타나지 않는다.

- `companion`은 품는 알의 `speciesId`와 독립이다. 기존 친구가 낚시하는 동안 새 알의 진행도를 표시할 수 있다.
- `affinity.ready`는 준비 표시이며 부화 성공이 아니다. 차량은 호감도나 남은 시간을 계산하지 않는다.
- `transferResult`는 companion이 제거되어도 읽는다. 요청 ID·표시 ID·표시 revision이 일치하는 폰 결과만 인정한다.
- 요청 전송만으로 캐릭터를 제거하지 않는다. 확정 시 기존 달리기 프레임으로 퇴장하며 새로 선택된 다른 친구를 숨기지 않는다.
- 지연 시 결과 미확인으로 안내한다. 명시적 재시도는 같은 요청 ID를 사용하며 연결 종료·세션 교체 후 이전 요청을 자동 재전송하지 않는다.
- 잘못된 선택 필드는 해당 블록만 숨기며 정상 빈 거점으로 바꾸지 않는다. 낮은 revision, 같은 revision의 다른 내용, 세션 내 v2에서 legacy로의 역행을 거절한다.
- `game.ts`는 v2 연결 heartbeat가 아니다. Firebase 스트림 연결과 새 루트 수신을 별도로 확인한다. Firebase 연결은 폰 앱의 실행 여부를 보장하지 않는다.
- 거점은 주차에서 폰이 제공한 요약만 표시한다. 시설·훈련 해금이나 완료 판정을 만들지 않는다.
- 여행 후보는 수집 이력이 아닌 폰이 요청한 지역으로 고른다. 최대 3개/직선 120km는 제안 기준이다. 위치가 없으면 고정 후보를 거리 없이 보여 준다.
- 이미 목표 지역이면 폰에서 방문 확인하도록 안내한다. 내비 요청 접수는 안내 시작이나 방문 완료가 아니다. 미합의 여행 결과 이벤트는 발행하지 않는다.

## 기존 애니메이션 사용

기존 PR의 6종 캐릭터 달리기·잠자기·낚시 스프라이트를 재사용한다. 주행은 달리기, 주차 기본은 낚시이며 잠자기도 선택할 수 있다. 새 이미지나 프레임을 생성하지 않는다. 미리보기의 입력과 이동 수락은 모의 상태임을 표시한다.

## 검증 경계

순수 상태 흐름·파서 회귀, Android 빌드와 에뮬레이터 미리보기는 로컬에서 검증한다. 실제 폰→Firebase→Pleos 왕복, Gleo 명령 등록·음성, 실제 차량 주차 판정과 내비 SDK, 주행 애니메이션 허용 여부는 별도 실기 검증 대상이다. 실기 체크리스트와 캡처는 Git에 올리지 않는 `tasks/todo.md`에 보관한다.
