# 주행 자동 낚시와 주차 조작

기준: [PR #100](https://github.com/Allo-MJU/allo/pull/100)의
[거점 구현 문서](https://github.com/Allo-MJU/allo/blob/feat/base-camp/docs/base-camp.md).
사용자 확정: 기존 목재·돌·식재료 수급을 낚시로 표현한다. 물고기 재화나 물고기 도감을 신설하지 않는다.

## 화면 경계

- 주행: 선택된 차량 동행 캐릭터의 자동 낚시와 짧은 안내만 표시한다. 버튼, 탭, 도감·거점 조작을 노출하지 않는다. 알/미선택/연결 끊김 상태 안내는 보존한다.
- 주차: 기존 홈·거점·여행·폰 공유 등 확인과 조작 화면을 허용한다. 현재 거점 탭은 폰에서 받은 요약이며 건설·요리·훈련과 도감 편집은 폰 기능이다. 새 차량용 편집기를 구현했다고 간주하지 않는다.
- 신호 대기의 속도 0은 주차로 취급하지 않는다. 실제 P 기어, 차량 UX 허용, 최신 주차 판정이 확인되어야 조작 화면이 열린다. 미확인·제한·연결 끊김에서는 조작을 닫는 기존 정책을 유지한다.
- 낚시 연출은 속도에 따라 빨라지거나 급감속에 넘어지지 않는다. 신선한 D 기어 차량 신호, 폰 연결, 포그라운드, 시스템 모션 설정을 따르며 중단 시 정지한다.

## PR #100 보상 계약 보존

실제 관측 거리 1,000m당 목재·돌·식재료 각각 1개를 지급한다. 잔여 거리, 중복·역순·거리 후퇴 방지, 재연결/복귀 기준점, 저장 성공 후 공개는 폰의 거점 로직 책임이다. 기존 60초 간격 창밖 보기 활동 보상도 변경하지 않는다.

차량 애니메이션은 타이머·프레임·물고기 동작 완료로 보상을 지급하지 않는다. 재료 개수, 보상 성공 팝업, 신규 도감 기록을 만들어 표시하지 않는다. 주행 화면은 `fishing-v1`의 주차 낚시 시작/재개 요청을 보내지 않는다. 기존 주차 낚시 프로토콜과 자동 주행 수집 연출은 독립적이다.

PR #100 head `979b281`의 거점 core/controller/store를 통합했다. 기본 AlloApp은 실제 feed에 default 프로필, FakeVehicleFeed에 demo 프로필을 생성하고 소유·해제한다. 기존 GameController의 단일 차량 구독을 재사용해 관측 거리를 전달하며, 페어링 직후부터 알/동행 선택 여부와 무관하게 재료를 수집한다. 복귀·알 시작으로 구독 재시작·stream 오류 때 새 거리 기준점을 잡는다.

거점 저장 성공 후 listener가 저장된 상태를 투영하고 기존 publishGame 전체 쓰기 큐에 collectionSummary/baseSummary를 합성한다. 기존 durable gameRevision 예약을 재사용하며 별도의 Firebase 부분 쓰기를 만들지 않는다. 저장 실패·지연 중에는 이전 공개 상태를 유지한다. 앱 복귀와 저장된 부화/도감 새로고침 때 거점 소유도 갱신한다. 실제 기기·운영 Firebase 페어링은 별도 실기 검증 대상이다.

## 주차 확인 화면 (후속 변경)

주차 홈의 낚시 시작·이어하기·쉬기 버튼을 제거했다. 프로덕션 경로는 기존 fishing-v1 상태가 남아 있어도 주차 낚시 화면으로 자동 진입하지 않는다. 기존 fishing-v1 presence는 active=false/parkedAllowed=false로 게시하고 요청을 거절해 숨겨진 활동이 진행되지 않게 한다. 개발용 LocalFishingDemo에만 별도 프로토콜 검증 버튼을 남긴다. 주차 화면은 홈·도감·이야기·거점·여행·폰 공유 탭을 제공한다. 기존 이야기 질문 버튼과 연결/종 검증을 유지한다. 홈에서는 보유 재료와 도감/거점 진입을 제공하고, 도감은 저장된 수집 종만 보여준다. 거점에서는 기존 역할·시설·활동 요약을 표시한다. 도감 항목과 재료 수량은 추정하지 않는다.

### 선택적 차량 표시 확장: collectionSummary v1

이 블록은 PR #100에 이미 있는 계약이 아니라 이번 차량 화면을 위한 **선택적 읽기 계약 확장**이다. PR #100의 게임 규칙과 저장 모델은 변경하지 않는다. 기본 폰 앱의 게시 어댑터가 연결되어 있으며, 이전 버전이나 거점 로드 실패 상태에서는 ‘정보 대기 중’을 표시한다.

`contractVersion=2` game snapshot에 다음 블록을 추가로 받을 수 있다:

```json
{
  "collectionSummary": {
    "version": 1,
    "wood": 12,
    "stone": 8,
    "ingredient": 5,
    "speciesIds": ["road_sprout", "puddle_pip", "lamp_moth"],
    "speciesCount": 3
  }
}
```

숫자는 저장된 **현재 보유량**으로, 이번 주행만의 획득량이나 누적 획득량이 아니다. PR #100은 주행·창밖 보기 보상을 함께 보유량에 합산하므로 화면도 이를 구분해 설명한다. 폰 어댑터는 저장 완료된 BaseCamp 재료와 정상 읽기·저장된 도감 소유의 중복 제거 종ID를 기존 gameRevision 갱신에 포함한다. 개체 ID나 원본 도감을 수정하지 않는다.

음수·소수·숫자 문자열·중복/잘못된 종ID·미지원 버전은 블록 오류로 처리한다. 블록 누락은 0개/빈 도감으로 취급하지 않는다. 연결이 끊기면 상단의 ‘마지막으로 받은 상태’로 구분한다. 미리보기만 예시 12/8/5개와 3종을 제공하며 테스트 데이터 배너를 유지한다. `--ez missingCollection true`로 미연동 상태를 확인한다.


시설은 baseSummary.facilityLevels(0~3단계), 병렬 작업은 activeTaskKinds 전체, 음식 재고는 foodInventory, 요리 도감 누적 제작 횟수는 recipeBook에 전달한다. PR #100에 최근 음식 소비 시각이 없으므로 lastMealId를 임의 추정하지 않는다. Firebase가 빈 배열/맵을 생략할 때 수집 종은 speciesCount=0으로 정상 빈 도감을 확인하고, 빈 작업·음식 목록은 빈 상태로 읽는다. 물고기 도감을 만들지 않는다.

검증: 실제 거점 규칙·저장소를 사용하는 폰 통합 테스트로 페어링 직후1km 보상, 저장 지연/실패, 도감·시설 변경의 새 revision, 복귀/stream 오류 기준점, 중복/역순 신호를 확인한다. 기본 앱 APK와 차량 APK를 빌드한다. 예시 미리보기 앱은 시안 검증용으로 별도 유지한다.

## 주행 전용 자세 경계

낚시 자세는 연결된 상태에서 최신 D 기어 신호가 확인된 Driving 화면에만 사용한다. 세션 종료는 잠자는 모습, 연결 끊김·저장·선택 대기 등은 기본 쉬는 모습이며, 기존 개발용 Fishing 상태 화면에도 낚시 자세를 재사용하지 않는다. 주행 제한 화면에서 실제 주행 신호나 폰 연결이 없으면 낚시 자세·자동 낚시 제목을 표시하지 않는다.
