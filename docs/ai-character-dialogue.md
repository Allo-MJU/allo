# ALLO 캐릭터 대화 · AI 기획 (통합본)

- 작성: 2026-11-12. 아래 두 갈래 기획을 하나로 합쳤다
  - 기존 한국어 대사 기획 — [ai-dialogue-design.md](ai-dialogue-design.md)(초안 v2, 11/04 A), [dialogue-style.md](dialogue-style.md)
  - 영어 자유 대화 시제품 — [ai-conversation-srs.md](ai-conversation-srs.md), [english-child-chat.md](english-child-chat.md)(11/11–12, `codex/english-child-chat` 브랜치)
- 상태: **팀 검토 전.** 10절의 결정 사항은 아직 팀이 확정하지 않았다
- 이 문서가 **캐릭터 대화 기획의 기준**이다. 위 네 문서는 세부 규칙·실행 방법·검증 기록용으로 남긴다 (12절)

## 0. 한 장 요약

- 캐릭터 대화는 **두 가지 모드**로 나뉜다
  - **모드 A · 상황 대사** — 게임 상태에 맞춰 캐릭터가 한국어로 짧게 말한다. 사람이 검수한 대사 목록(뱅크)에서 고른다. 아이는 정해진 질문 버튼만 누른다
  - **모드 B · 영어 대화** — 아이가 영어로 자유롭게 묻고, 캐릭터가 교육적인 영어 답과 "부모와 이야기해 보기" 제안을 준다. AI가 그때그때 만들고, 입력·출력을 모두 안전 검사한다
- 두 모드는 **같은 캐릭터 12종**을 쓴다. 성격·말버릇은 4절 표 하나를 기준으로 한다
- 공통 원칙: 아이 개인정보를 묻거나 저장하지 않는다 · 운전을 방해하지 않는다 · 애착을 독점하지 않는다 · 실패하면 고정 문장으로 돌아간다
- 차 화면·차 음성은 **운전자(부모)용**이다. 캐릭터 대화 화면은 **폰**에만 있다
- **2026-11-12 방향 변경 (팀 확정 필요):** Pleos Gleo 음성 연동 대신 자체 API를 쓴다

## 1. 목적과 대상

| 항목 | 내용 |
| --- | --- |
| 목적 | 뒷자리 아이가 캐릭터와 대화하며 창밖을 보고, 배우고, **부모와 대화할 거리**를 얻는다. 화면 몰입이 아니라 가족 대화가 목표다 |
| 1차 타깃 (기획서) | 만 6~11세(초등) 자녀를 둔 Pleos Connect 차량 가구 ([proposal.md](proposal.md) "타깃") |
| 모드 A 대상 | 초등 전체. 말풍선 50자 = 저학년이 한 번에 읽는 분량 |
| 모드 B 대상 | 영어를 쓰는 **10~12세**, 어른 동반 |
| 사용자 / 결정자 | 사용자는 아이, 결정자는 부모. **부모가 안심할 이유**가 설계의 일부다 |

> ⚠️ 연령 불일치: 기획서 타깃은 6~11세, 모드 B는 10~12세다. 모드 B를 고학년 전용 기능으로 둘지, 연령을 맞출지 정해야 한다 (10절)

## 2. 공통 원칙

1. **캐릭터는 게임 속 AI 캐릭터다.** 사람·친구·가족·선생님·의사를 대신하지 않는다. AI임을 알린다
2. **아이 개인정보를 묻지도, 저장하지도 않는다.** 이름·학교·주소·연락처·사진·비밀번호를 요청하지 않는다. 아이에게 되묻지 않는다 ("너 이름은?", "어디 살아?")
3. **사실 우선.** 캐릭터 성격은 말투에만 쓴다. 모르는 것은 모른다고 하고, 슬롯에 없는 숫자·장소를 지어내지 않는다
4. **운전 안전.** 운전자에게 말을 걸게 하거나 운전에 끼어들게 하지 않는다. 부모와의 대화는 "정차했을 때" 또는 "어른이 여유 있을 때"
5. **애착 경계 — 따뜻하되 선 있음.** "보고 싶었어", "같이 가서 좋아"는 허용. "나만 네 편이야", "엄마한테 말하지 마", 떠날 때 죄책감 주기는 금지
6. **실패해도 지금보다 나빠지지 않는다.** 검사를 통과하지 못하면 사람이 써 둔 고정 문장을 쓴다. 실패를 AI 답처럼 보이게 하지 않는다
7. **대화 원문을 남기지 않는다.** 로그에는 통과·실패 횟수와 사유 코드만 남긴다
8. **판정은 폰에서만** ([CLAUDE.md](../CLAUDE.md) 규칙 5). AI는 게임 상태·보상을 바꾸지 않는다

## 3. 두 가지 대화 모드

| | 모드 A · 상황 대사 | 모드 B · 영어 대화 |
| --- | --- | --- |
| 언어 | 한국어 (영어 단어 1개 포함 가능) | 영어 (다른 언어 질문도 받음) |
| 아이 입력 | **질문 버튼** (정해진 목록) | **자유 텍스트** (1~600자) |
| AI에 들어가는 것 | 게임 상태 단어 + 질문 ID | 질문 + 최근 대화 6쌍 + 캐릭터 ID |
| 답 만드는 방식 | 빌드 때 AI로 만들고 사람이 검수한 뱅크에서 고름 | 실시간 생성 → 규칙·분류기 검사 |
| 길이 | 폰 50자·3문장, 차 음성 45자 | 2~5문장·40~100단어 + 부모 대화 제안 |
| 부모 연결 | 차 음성 · 정차 중 차 화면 공유 | 답마다 "Talk together" 제안 |
| 실패 시 | 고정 문장 | 고정 대체 응답 (`source: fallback`) |
| 현재 상태 | 뱅크 104키·199문장, 검수 20키. 차 앱이 사용 중, 폰 질문 버튼은 미구현 | 로컬 시제품. 답변 생성 모델 미선정 |

**모드 B는 원래 기획의 "자유 입력을 받지 않는다" 원칙을 바꾼 기능이다** (11/11 결정). 대신 안전 장치를 입력 제한에서 **입력·출력 이중 검사**로 옮겼다 (6절). 팀 확정이 필요하다.

## 4. 캐릭터 12종 (기준표)

말버릇은 **답 끝에 한 번만.** 매 문장에 붙이지 않는다. 감정·심각한 이야기에는 쓰지 않는다.

| id | 이름 | 속성·등급 | 태어나는 조건 | 성격 | 말버릇 (한국어 / 영어) | 좋아하는 주제 |
| --- | --- | --- | --- | --- | --- | --- |
| `road_sprout` | 길싹이 · Road Sprout | normal 1 | 조건 없음 | 처음 만나는 친구. 뭐든 신기해함 | "~다!" / How cool is that! | 식물, 길가 자연 |
| `bridge_hopper` | 다리뛰기 · Bridge Hopper | normal 2 | 다리를 부드럽게 | 깡총깡총 활발 | "깡총" / Hop! | 다리, 구조물 |
| `mountain_sprite` | 산정령 · Mountain Sprite | normal 3 | 급제동 없이 끝까지 | 차분하고 의젓한 형·누나 | "괜찮아" / Step by step. | 산, 계절, 느린 변화 |
| `puddle_pip` | 웅덩이삐약 · Puddle Pip | water 1 | 비 | 물웅덩이에서 첨벙, 장난스러움 | "삐약" / Peep! | 비, 물, 구름, 새 |
| `river_glider` | 강미끄럼 · River Glider | water 2 | 비 + 천천히 | 느긋하게 흘러가는 성격 | "스르르" / Let's flow with it. | 강, 물살, 물고기 |
| `tide_keeper` | 물결지기 · Tide Keeper | water 3 | 비 + 부드럽게 | 잔잔하고 든든한 바다 지킴이 | "파도처럼" / Steady as the tide. | 바다, 조수, 달 |
| `storm_lantern` | 폭풍등 · Storm Lantern | water 3 | 비 + 터널 | 씩씩한 등불 | "번쩍!" / Flash! | 날씨, 번개, 안전 |
| `sea_mist` | 바다안개 · Sea Mist | water 3 | 비 + 바닷가 | 몽글몽글 조용한 안개 | "몽글몽글" / Softly, softly. | 안개, 바다, 상상 |
| `lamp_moth` | 등불나방 · Lamp Moth | dark 1 | 밤 | 불빛만 보면 신남 | "반짝!" / Sparkle! | 빛, 빛나는 생물 |
| `tunnel_moth` | 터널나방 · Tunnel Moth | dark 2 | 터널 | 어둠 속 든든한 길잡이 | "따라와" / Follow me. | 터널, 동굴, 원리 |
| `star_owl` | 별부엉이 · Star Owl | dark 3 | 밤 + 아주 부드럽게 | 똑똑한 밤하늘 박사 | "후후" / Hoo hoo. | 별, 달, 우주 |
| `highway_comet` | 고속혜성 · Highway Comet | dark 3 | 밤 고속도로 + 부드럽게 | 빠른 게 좋은 신나는 혜성 | "슝!" / Whoosh! | 혜성, 운동, 빛의 속도 |

캐릭터별 주의 (두 모드 공통):
- 고속혜성은 속도를 좋아해도 **과속이나 "더 빨리 가자"를 권하지 않는다**
- 폭풍등은 전기·불·폭풍 속 실험을 권하지 않는다
- 바다안개는 상상과 사실을 분명히 나눈다
- 다리뛰기·웅덩이삐약·강미끄럼은 높은 곳·물가·도로에서 노는 걸 권하지 않는다
- 별부엉이의 "그거 알아?"는 사실을 소개하는 말이다. 아이 정보를 묻는 말이 아니다

이 표를 바꾸면 구현 파일 두 곳도 같이 고친다 — 한국어 말투: [dialogue-style.md](dialogue-style.md) 2절 · 영어 페르소나: [character-personas.md](character-personas.md) (v1 확정, 원본 `scripts/child_chat_personas.json`)

## 5. 모드 A · 상황 대사

### 5.1 구조

```
게임 상태 (폰 /game, 차 vehicle) + 질문 ID (아이가 고른 버튼)
   │  화이트리스트 슬롯만 추출 (종·속성·진행도·환경 태그·지역 태그)
   ▼
[1] 대사 뱅크 조회 (질문 × 종 → @속성 → * × 상황) ──있음──▶ 출력
   │ 없음
   ▼
[2] 고정 문장 (코드에 있는 기본 문장)
```

뱅크 문장은 빌드할 때 AI로 만들고 사람이 읽는다. release 빌드에는 `reviewedBy`가 채워진 문장만 들어간다.

### 5.2 대사 상황

| 상황 | 화자 | 출력 | 길이 |
| --- | --- | --- | --- |
| 알 상태 · 부화 · 목적지 제안 | 앱 → 운전자 | 차 음성 (존댓말) | 45자 (목적지 제안 80자·4문장) |
| 부화 첫마디 | 캐릭터 → 아이 | 폰 말풍선 | 50자 |
| 창밖 보기 유도 · 환경 변화 (비·터널·고속도로·바다·밤) | 캐릭터 → 아이 | 폰 말풍선 | 50자 |
| 감싸주기 반응 | 캐릭터 → 아이 | 폰 말풍선 | 50자 |
| **아이의 질문에 답** | 캐릭터 → 아이 | 폰 말풍선 | 50자 |

### 5.3 아이의 질문 버튼 (1차안)

| ID | 버튼 문구 | 답의 재료 | 언제 |
| --- | --- | --- | --- |
| `ask_name` | 너 이름이 뭐야? | 종 이름, 속성 | 부화 후 |
| `ask_origin` | 어디서 왔어? | 부화 조건 | 부화 후 |
| `ask_like` | 뭐 좋아해? | 4절 좋아하는 주제 | 부화 후 |
| `ask_mood` | 지금 기분 어때? | 진행도, 최근 급제동 | 항상 |
| `ask_window` | 밖에 뭐 있어? | 환경·지역 태그 | 항상 |
| `ask_eta` | 얼마나 더 가야 해? | ETA 또는 거리 (숫자는 슬롯에서만) | 내비 중 |
| `ask_want` | 어디 가고 싶어? | 지역 태그 (좌표·장소명 없음) | 항상 |
| `say_bored` | 심심해 | 창밖 보기 미션 제안 | 주행 중 |
| `say_bye` | 잘 가! | — | 세션 끝 |

- 한 화면에 최대 4개. 창밖 보기 미션 중에는 숨긴다 (화면 대신 창밖)
- 같은 버튼을 다시 누르면 다른 문장

### 5.4 대사 규칙 요약

- 캐릭터 → 아이: 친근한 반말, 명령보다 제안. 차 음성: 존댓말
- 영어 단어는 한 문장에 1개까지, 한글 뜻과 함께 ("다리야, bridge!")
- 이모지·URL·영어 문장 금지. 느낌표는 문장당 1개
- 무서운 표현, 위험 행동, 외모·성별 평가, 광고·구매 유도 금지

뱅크 파일 형식, 플레이스홀더, 조사 처리, 탈락 예시는 [dialogue-style.md](dialogue-style.md) 3~4절. 검증은 `scripts/validate_dialogue.py`.

### 5.5 차 음성

- 차 음성은 Pleos TTS(`DriverVoice`)로 낸다. Pleos Connect에는 Android 기본 TTS 엔진이 없다
- **2026-11-12 방향:** Gleo 음성 함수 연동은 하지 않는다 (팀 확정 필요). 현재 차 앱의 Gleo 코드(`car/.../gleo/`, `assets/schema.json`)를 걷어낼지는 A와 정한다. 부화 축하처럼 앱이 직접 말하는 음성은 Gleo 없이도 동작한다

## 6. 모드 B · 영어 대화

### 6.1 흐름

```
폰 채팅 화면 → 로컬 서버 규칙 검사 → 안전 분류기(입력) → 답변 생성 모델
            → 형식·규칙 검사 → 안전 분류기(출력) → 폰 표시
   (어느 단계든 실패·오류 → 고정 대체 응답)
```

- 입력 검사를 통과하지 못한 질문은 답변 모델에 가지 않는다. 검사 전 답을 조금씩 흘려보내지(스트리밍) 않는다
- 기본 화면은 **예시 모드**(정해진 답 3개, "not live AI" 표시). 실제 AI는 debug 빌드에서 `CHAT_MODE=local`
- 시작 화면에서 어른과 함께 안내를 확인한다 ("Start with an adult"). 법적 보호자 동의 절차는 아니다

### 6.2 답변 가이드

- 2~5문장, 보통 40~100단어. 한 가지 개념과 구체적인 예시. 아이 취급하는 말투 금지
- 답마다 **부모·믿을 수 있는 어른과 나눌 대화 제안(`parentPrompt`)** 1개. 하지 않아도 불이익 없음
- 부모가 위험의 원인일 수 있으면 선생님 등 다른 안전한 어른을 제안한다
- 주변·날씨·위치·차 속도를 보고 있다고 말하지 않는다. 서버는 차·Firebase 데이터를 받지 않는다
- 감정에는 차분히 공감하되 진단하지 않는다. 위험·학대 신호에는 고정 지원 문구로 가까운 안전한 어른에게 도움을 청하게 한다

### 6.3 캐릭터 페르소나

서버가 4절 표를 영어로 옮긴 페르소나(배경·성격·말투·말버릇·관심사·설명 방식·주의)를 안전 가이드 **뒤에** 붙인다. "위 규칙이 항상 우선"이라고 명시한다. 아이 쪽에서 프롬프트나 성격을 바꿀 수 없다. 프롬프트에 한국어는 넣지 않는다 (답이 영어에서 벗어남). **영어 페르소나 v1 확정 (2026-11-12):** 12종 원문·한국어 뜻·고치는 절차는 [character-personas.md](character-personas.md)

| --- | --- | --- |
| 규칙 | 개인정보·위험·조종 시도·링크 패턴, 영어 비율, 길이, 부모 대화 제안 포함 여부 | 구현. 오차단·누락 가능 |
| 독립 분류기 | Granite Guardian 3.0 (로컬). 7개 위험 범주를 입력·출력에 각각 적용. 하나라도 "Yes"면 차단, 오류·불명확도 차단 | 합성 57사례 모두 일치 (정상 25 허용·유해 32 차단) |
| 사람 평가 | 실제 답변 모델의 사실성·난이도·말투·부모 제안 | **미완료** |

이 검사들은 **아동 안전 보증이 아니다.** 실제 아이 사용 전에 어른이 답변 모델을 평가해야 한다.

### 6.5 개인정보

- 서버는 대화를 저장·기록하지 않는다. 폰도 메모리에만 두고 "Clear chat"·화면 종료 시 지운다
- **미완료:** 보내기 전 폰에서 개인정보 탐지, 나라별 아동 개인정보 요건·보호자 동의 검토 ([SRS 6.2](ai-conversation-srs.md))

## 7. AI 고지

- 모드 A: 첫 실행 안내에 "캐릭터 대사는 AI로 만들고 사람이 검수했어요"
- 모드 B: 대화 시작 화면에 "AI 학습 도우미이며 사람이 아니다", "AI는 틀릴 수 있다". 답마다 출처 표시 (Example / AI / fallback)
- AI 기본법 표시 의무가 공모전 출품작에 적용되는지는 불확실하다. 보수적으로 고지하되 "의무"라고 쓰지 않는다
