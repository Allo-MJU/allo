# 미수집 친구·완성 보상·마을 표시 선택

2026-11-15 사용자 지시 기준. 12종 수집 완료 보상은 사용자 확인으로 베리 간식 3개/여행 1회다.

## 확정 범위

- 이미 도감에 기록된 종은 새 부화 결과에 나오지 않는다. 기존 소유 개체와 과거 중복 기록은 유지한다.
- 기존 환경·주행 판정에 맞는 미수집 후보를 우선한다. 해당 후보가 없으면 남은 미수집 종 중 선택하여 수집이 막히지 않게 한다. 이 fallback은 구현 판단이며 실제 기상·위치 관측을 조작하지 않는다.
- 현재 출현 카탈로그의 12종을 모두 소유한 이후의 새 여행에는 알 대신 기존 `berry_snack` 3개를 지급한다. 같은 여행 재연결·앱 재시작·저장 재시도는 중복 지급하지 않는다. 12번째 부화가 일어난 여행에는 추가 간식을 지급하지 않는다.
- 간식은 기존 거점 음식 보관함에 저장한다. 도감/거점 로드 실패를 수집 완료나 빈 도감으로 간주하지 않는다. 저장이 실패하면 재시도할 수 있어야 한다.
- 마을에 표시할 소유 개체를 최대 4마리 선택하고 로컬에 저장한다. 선택은 종이 아니라 소유 개체 ID 기준이다. 선택 저장 전후 기존 역할·작업·동행 선택을 바꾸지 않는다.
- 기존 저장에는 처음 4개체를 기본 표시한다. 사용자가 명시적으로 0~4마리를 선택한 이후 새 친구를 자동으로 끼워넣지 않는다. 없는 개체 ID/중복/5마리 이상 요청은 검증한다. 체험·실제 프로필은 분리한다.
- 현재 책 도감과 마을의 색·레이아웃을 유지하고 마을의 ‘표시 친구 선택’에서 선택/해제·선택 수·저장을 제공한다. 저장 실패를 성공으로 표시하지 않는다.

## 접근법과 선택 이유

1. 종 선택 뒤 중복이면 다시 추첨: 후보가 소진되면 반복·누락 위험이 있어 사용하지 않는다.
2. 미수집 후보를 먼저 만드는 방식: 기존 판정 우선순위를 재사용하며 중복을 확실히 막으므로 채택한다.
3. 수집 전체와 마을 UI를 새 서버 계약으로 이전: 필요하지 않으므로 기존 폰 로컬 저장과 권한 경계를 유지한다.

간식 지급은 기존 거점의 저장 트랜잭션 안에 여행별 receipt와 재고 증가를 함께 기록한다. 마을 표시 선택은 독립 로컬 설정으로 관리해 주행 판정·기지 경제·Firebase wire를 변경하지 않는다.

## 후순위와 제안 전용 범위

- 짧은 여행 부화 제한시간, 사진 업로드 대기시간, 작업 시간/효과 안내는 수정하지 않는다.
- 알 돌보기 종료 후의 상태 안내는 별도 구체안만 작성하고 제품 코드에는 적용하지 않는다.
- APK 재빌드·설치·배포는 이 요청 범위에 포함하지 않는다. 기존 연결 복구 및 동시 작업 파일은 보존한다.

## 검증

미수집 우선/조건 불일치 fallback/마지막 1종/전체 완료, 여행별 간식 3개와 재연결·재시작·저장 실패·12번째 여행 중복 방지, 선택 0~4개체/다섯 번째 거부/같은 종 다른 개체/복원/프로필 격리/저장 실패, Unity 실제 선택 UI와 기존 마을 상호작용 유지.
