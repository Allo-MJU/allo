# 여행당 한 알과 캐릭터 탭 대화

2026-11-14. 사용자 기능 변경 요청과 ‘미부화 알은 다음 여행에 이어 키운다’ 답변을 구현 기준으로 한다.

## 확정 동작

- 차량 QR/코드 페어링 성공 후 폰은 알 하나를 자동 준비한다. 차 안의 알 크기 선택·시작 버튼과 기존 친구 선택창을 제거한다.
- 같은 여행의 재페어링·코드 재발급·앱 재시작으로 새 알을 받지 않는다. 부화·실패·버리기 후에도 같은 여행에서는 추가 지급하지 않는다.
- 미부화 알이 있으면 다음 여행에 이어 키운다. 그 여행에는 별도의 새 알을 주지 않는다. 이전 알의 진행·호감도·사진 완료·지급 ID를 보존한다.
- 40분 품기/30분 동행을 반복하는 지급 스케줄과 부화+30분 재지급을 없앤다. ETA 절반(분 내림), 80분 초과일 때 40분 품기, ETA 없을 때 거리 대체 등 부화 계산만 유지한다. 호감도·사진 퀘스트 자체를 없애지 않는다.
- 기존 친구는 친구 상세의 ‘차 안으로 불러오기’로 불러온다. 소유 개체를 검증한 뒤 차량 동행과 폰의 실제 표시·대화 대상을 같은 개체로 맞춘다.
- 불러오기만으로 긴 이야기나 음성을 자동 재생하지 않는다.
- 차 안에서 그 캐릭터를 짧게 누르면 머리 위에서 ‘나한테 궁금한 게 있는 거야?’라고 안내하고 ‘이야기 듣기’와 ‘말 걸기’ 두 선택지를 보여 준다.
- ‘이야기 듣기’는 고정 스토리의 저장된 장면을 페르소나에 맞게 말풍선/음성으로 들려준다. ‘말 걸기’는 기존 AI/음성 입력 경로를 연다. 상시 큰 설명 패널을 표시하지 않는다.

## 구현 판단

- 새 알의 기본 크기는 기존 기본값 small로 둔다. 무작위 크기나 새로운 희귀도 규칙을 추가하지 않는다.
- 여행 identity는 실제 차량 sessionId로 한다. 데모 여행에도 저장·복구되는 독립 identity를 둔다. 이 기록은 기존 namespace/profile로 격리한다. 동일 앱 저장소 안의 보장이며 새 서버 계약은 만들지 않는다.
- 여행별 소비 기록은 tier별 checkpoint와 분리한다. 지급 또는 기존 알 승계의 확정 정보를 먼저 안전하게 저장하고 노출한다. 저장 실패·재시도·A→B→A 연결에서 중복 지급하지 않는다.
- 이전 부화 결과의 저장이 실패했다면 그 결과를 먼저 확정한다. 새 여행 알로 실패한 결과를 덮어쓰지 않는다.
- ETA 2분 미만 등 기존 부화 계획 보류 조건에서도 반복 지급을 만들지 않는다. 지급/이어하기 상태와 계획 보류를 구분한다.
- 알과 기존 친구의 공존을 허용하고 선택창을 강요하지 않는다. 친구를 불러오는 것은 해당 여행의 알 지급 권한과 무관하다.
- 새 상호작용은 현재 소유 개체와 캐릭터 hit를 일치시킨다. 머리 앵커는 CritterView.Top을 사용하고 화면 밖·대상 변경·다른 화면·실험 이야기/여행 노트·앱 중단 때 초대 UI와 늦은 대화를 닫거나 무효화한다.
- 마우스/터치의 짧은 탭과 쓰다듬기를 구분한다. 머리 위 버튼은 입력을 가로채 카메라 회전·중복 돌봄을 발생시키지 않는다.
- 음성/TTS/API 실패 때 짧은 안내와 텍스트 입력 대안을 제공하며 진도를 바꾸지 않는다. 최초 소개·3분 자동 초대가 새 클릭 기반 흐름을 우회하지 않도록 기본 자동 발화를 끈다.
- 기존 자유 AI·고정 스토리·학습 자료는 서버에서 재사용한다. 창밖 실험 모드와 동시에 말을 하지 않는다. 서버 연결 실패 시 앱은 연결 안내만 표시하며 개인 스토리 본문이나 AI 답변을 로컬에서 대신 생성하지 않는다.

## 검증 기준

페어링 최초 지급, 같은 세션 재접속/재시작/크기 변경 우회 차단, 긴 주행·부화 후 추가 지급 없음, 실패/버리기 후 추가 지급 없음, 미부화 A→B 승계와 B에서 중복 없음, A 재접속, 저장 실패 재시도, 데모와 실제 프로필 분리, ETA/거리 계산 유지, 친구 소유 검증과 정확한 개체 연결, 불러오기 자동 발화 없음, 캐릭터 탭 두 선택지, 잘못된 대상·늦은 응답·실험/노트 입력 배타성, 작은 화면 머리 위 UI 배치.

## 범위

기존 Kotlin QR 페어링은 유지한다. Firebase 필드나 차량 제어 권한은 새로 추가하지 않는다. 기존 사용자 저장소를 지우지 않는다. 상태/표시의 기존 wire 의미가 달라지는 부분은 현행 계약 문서에 동작 변경을 명시하고 과거 검증 기록을 덮어쓰지 않는다.

## 서버와 프론트 역할 — 사용자 추가 지시

- 대화 흐름과 고유 페르소나는 서버 코드에서 실행한다. 서버가 초대 문장, 이야기 본문, 다음 장면, 반복, 대화 응답과 허용 선택지를 결정한다.
- 인증된 `POST /v1/companion/turn`으로 invite/listen/next/repeat/chat 의도를 전달한다. 기존 chat endpoint는 호환용으로 유지한다.
- 앱은 소유 대상 검증, 입력 수집, 요청 취소/수명 관리, 서버가 승인한 장면 참조의 로컬 저장, 말풍선 배치·TTS 재생을 맡는다. 알 지급/부화의 기존 게임 판정 주체를 서버로 옮기는 변경은 아니다.
- 페르소나·고정 이야기 본문·지식 자료는 서버 카탈로그에만 둔다. 폰 번들은 종/스토리/버전/장면 ID 식별 메타데이터만 포함한다. 앱이 다음 장면을 계산하거나 서버 응답 없이 고정 스토리를 펼치지 않는다.
- invite/listen/next/repeat 같은 사전 작성 콘텐츠 응답은 서버에 모델 키가 없어도 가능하다. AI chat만 실제 제공자 설정을 필요로 한다. 이 구분을 오류 메시지와 검증 결과에서 유지한다.
- 대화 원문/음성의 영구 저장은 추가하지 않는다. 서버의 페르소나·학습자료가 사용자 입력으로 덮어써지지 않게 하고, 결과에는 요청/대상/스토리/버전 연관 정보를 포함한다.
