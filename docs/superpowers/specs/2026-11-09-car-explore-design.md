# 차 안·밖 탐험 게임 설계 (가로 화면, Unity)

작성 2026-11-09 · A(정세현) · 상태: **초안, 검토 대기**

## 1. 목표

뒷자리 아이가 휴대폰을 **가로로** 들고, 지금 타고 있는 차의 **안과 밖을 입체적으로 둘러보며** 노는 화면을 만든다.

- 화면을 좌우로 돌리고 앞뒤로 움직여 앞유리, 양 옆창, 뒷유리, 차 안 구석구석을 본다.
- 차 안의 좌석, 대시보드, 쿠션, 장난감 같은 것들이 하나하나 **물체(오브젝트)** 로 있고, 만지면 반응한다.
- 아이의 캐릭터와 모은 친구들이 차 안을 **돌아다니고, 물체 위에 올라가고, 창문에 달라붙는다.**
- 창밖 풍경은 실제 차 신호(지역·비·밤·터널·속도)에 따라 바뀌고 흘러간다.

### 사용자가 정한 것

| 항목 | 결정 |
| --- | --- |
| 일정 | 기능 동결(11/12)과 관계없이 완성도 있게 만든다 |
| 엔진 | Unity. 퀄리티를 우선한다 |
| 3D 모델 | 차 내부·물체·창밖 풍경은 A(Claude)가 스크립트로 만든다 |
| 캐릭터 | 2D로 둔다. D의 캐릭터 그림을 3D 공간에 세운다(빌보드) |
| 화면 방향 | 앱 전체를 가로 화면으로 바꾼다 |

### 이 문서가 가정한 것 (검토 때 확인)

- 탐험 화면은 **표시와 놀이 전용**이다. 부화·희귀도 판정은 지금처럼 `allo_core` 에서만 한다 (CLAUDE.md 규칙 5).
- Firebase 스키마(`schema.md`)는 바꾸지 않는다. Unity 는 Flutter 를 통해서만 데이터를 받는다.
- 주 시연 기기는 안드로이드 휴대폰이다. iOS 는 빌드만 깨지지 않게 유지한다.

## 2. 화면과 조작

### 2.1 시점

카메라는 뒷좌석 가운데, 아이 눈높이에 있다.

| 조작 | 동작 |
| --- | --- |
| 한 손가락 좌우 드래그 | 고개를 좌우로 돌린다 (360도. 앞유리 → 오른쪽 창 → 뒷유리 → 왼쪽 창) |
| 한 손가락 위아래 드래그 | 고개를 들고 숙인다 (±35도 제한) |
| 두 손가락 핀치 | 앞뒤로 움직인다. 뒷좌석 ↔ 앞좌석 사이 레일 위에서만 (멀미 방지) |
| 휴대폰 기울이기 (선택) | 자이로로 고개를 조금 따라 돌린다. 설정에서 끌 수 있다 |
| 물체·캐릭터 탭 | 반응한다 (2.3, 2.4) |

화면 위에는 최소한의 Flutter UI만 둔다: 돌아가기, 지금 장면 이름, 알 상태 한 줄.

### 2.2 차 안 물체

모두 둥근 모서리, 단색 재질의 **말랑한 장난감 느낌 로우폴리**로 만든다. 색은 Figma ALLO Design System 변수를 쓴다.

| 물체 | 반응 (탭) | 캐릭터가 하는 것 |
| --- | --- | --- |
| 앞좌석 2개 (등받이·머리받침) | 머리받침이 살짝 눌렸다 돌아온다 | 머리받침 위에 올라앉는다 |
| 뒷좌석·가운데 팔걸이 | 팔걸이가 열리고 안에 작은 물건 | 팔걸이 위에서 쉰다 |
| 대시보드 | 차량 화면에 알로 로고가 반짝인다 | 대시보드 위를 걸어 다닌다 |
| 룸미러 + 알 장식 | 장식이 흔들린다 | 매달린다 |
| 창문 4곳 (앞유리·옆창·뒷유리) | 손가락으로 김 서린 유리에 그림 | 유리에 달라붙어 밖을 본다 |
| 쿠션·인형·물병·컵홀더 | 굴러가거나 통통 튄다 (물리) | 밀고 다니거나 위에 올라간다 |
| 실내등 | 켜고 끈다 | — |
| 뒷선반 | — | 누워서 하늘을 본다 |

### 2.3 캐릭터

- 2D 그림을 카메라 쪽으로 세운 빌보드다. 그림은 D의 `species.sprite` 와 같은 파일을 쓰고, 없으면 임시 실루엣을 쓴다.
- 입체감을 위해 발밑에 그림자를 깔고, 움직일 때 몸을 기울이고 통통 튀며 늘었다 줄었다 한다(스쿼시·스트레치).
- 등장: 지금 동행 중인 캐릭터 1 + 모은 친구 중 최대 3. 고르는 규칙은 지금 `eligibleFriends` 와 같은 자리 하나에 둔다 (나중에 속성별 등장으로 바꾼다).

**행동** (상태 기계, 무작위 시간·목적지)

| 상태 | 내용 |
| --- | --- |
| 쉬기 | 지금 자리에서 두리번거리거나 존다 |
| 걷기 | 같은 면 위의 다른 지점으로 걸어간다 |
| 점프 | 이어진 다른 면으로 포물선을 그리며 뛴다 (좌석 → 팔걸이 → 대시보드) |
| 창문 붙기 | 유리에 달라붙어 창밖을 본다. 밖에 볼거리(갈매기·터널 조명)가 있으면 더 자주 |
| 반응 | 차 신호에 반응한다 (아래 표) |

| 차 신호 | 캐릭터 반응 |
| --- | --- |
| 급제동·급조향 | 앞으로 미끄러지거나 데굴 구른다. 물체도 같이 쏠린다 |
| 비 시작 | 창문으로 달려가 빗방울을 본다 |
| 터널 진입 | 실내등 근처로 모이거나 서로 붙는다 |
| 밤 | 졸거나 잠든다 |
| 정차 (P) | 자유롭게 돌아다니는 시간이 늘어난다 |

### 2.4 차 밖

창밖은 실제 3D 공간이다. 차는 제자리에 있고 **세상이 뒤로 흐른다**.

- 도로와 길가를 **청크(조각)** 단위로 만들어 앞에 붙이고 뒤에서 떼어 낸다(무한 스크롤). 청크 길이는 50m 정도로 한다.
- 장면별 청크 세트: 시골길, 바다, 산, 도시, 고속도로, 터널. 지금 Flutter 판에서 정한 요소 목록(건물 2~3줄, 간판, 가로수, 사람, 농가, 돛단배, 등대, 산맥 등)을 그대로 3D로 옮긴다.
- 먼 산과 하늘은 큰 반구와 원통 배경에 그린다. 안개(fog)로 대기 원근을 낸다.
- 장면이 바뀌면 다음 청크부터 새 장면을 붙여 자연스럽게 넘어간다. 터널은 입구 청크를 거친다.
- 밤·비는 조명, 하늘, 파티클(빗줄기·창문 물방울), 와이퍼로 표현한다. 와이퍼 속도는 `wiperLevel` 을 따른다.

## 3. 구조

```
Flutter 앱 (가로 고정)
 ├─ 기존 화면 (페어링·알 품기·부화·동행·도감)  ← 가로 레이아웃으로 개편 (B)
 └─ 탐험 화면 ──────────── UnityWidget (flutter_unity_widget)
        │  ▲                     │
        │  │ JSON 메시지          ▼
        │  └──────────── Unity (Unity as a Library)
        │                  ├─ Bridge        메시지 받기·보내기
GameController             ├─ CameraRig     둘러보기·자이로·레일 이동
 (allo_core 판정)           ├─ Cabin         차 내부 물체·상호작용
 /vehicle 스냅샷 ──────────►├─ World         창밖 청크·장면·날씨
 모은 캐릭터 목록 ─────────►├─ Critters      캐릭터 빌보드·행동
                           └─ Fx            비·조명·와이퍼
```

- Flutter 가 지금처럼 `/vehicle` 을 구독하고 판정한다. Unity 에는 **표시에 필요한 것만** 넘긴다.
- Unity 는 Firebase 에 접근하지 않는다. 위경도도 받지 않는다 (CLAUDE.md 규칙 2. `envTags` 만 넘긴다).

### 3.1 Flutter ↔ Unity 메시지 contract (초안)

모두 JSON 한 줄이다. 버전 필드를 둬서 양쪽이 따로 바뀌어도 깨지지 않게 한다.

**Flutter → Unity**

```json
{"v":1,"type":"scene","kind":"coast","night":false,"highway":false,"rain":2,"speedKph":62.0,"moving":true}
{"v":1,"type":"jolt","kind":"brake"}
{"v":1,"type":"cast","companion":{"id":"sea_mist","sprite":"species/sea_mist.png","attribute":"water"},
 "friends":[{"id":"puddle_pip","sprite":"species/puddle_pip.png","attribute":"water"}]}
{"v":1,"type":"settings","gyro":true,"reducedMotion":false}
```

- `scene` 은 지금 `WindowScene` 을 그대로 옮긴 것이다. 장면 깜빡임 방지(`SceneStabilizer`)는 Flutter 쪽에서 이미 적용한 값을 보낸다.
- `jolt` 는 `harshBrake`·`harshSteer` 가 늘었을 때 한 번 보낸다.

**Unity → Flutter**

```json
{"v":1,"type":"ready"}
{"v":1,"type":"tap","target":"critter","id":"sea_mist"}
{"v":1,"type":"tap","target":"object","id":"mirror_charm"}
```

- `tap` 은 놀이 기록과 소리용이다. 게임 판정에는 쓰지 않는다. 돌봄 횟수에 넣을지는 C 와 정한다(열린 질문).

## 4. 3D 에셋 만들기

- **Blender Python 스크립트**로 모델을 만든다. 둥근 상자·원기둥·곡면을 조합하고 베벨로 모서리를 둥글린다. 결과는 `.glb` 로 내보낸다.
- 스크립트마다 미리보기 렌더(PNG)를 같이 뽑아서 모양을 확인하고 고친다. 사람이 Blender 를 열지 않아도 된다.
- 재질은 단색 + 살짝 광택. 색은 Figma 변수 값을 한 파일(`palette.py`, `Palette.cs`)에 모아 둔다.
- 물체 목록: 차체 내부 셸, 앞좌석×2, 뒷좌석, 팔걸이, 대시보드, 운전대, 룸미러·장식, 문 패널×4, 쿠션, 인형, 물병, 컵홀더, 실내등.
- 창밖 목록: 도로 청크, 가로수 3종, 건물 5종(층수는 스크립트로 바꿈), 농가, 비닐하우스, 전봇대, 가로등, 신호등, 자동차 4종, 버스, 돛단배, 등대, 바위, 방음벽, 터널 단면.
- 캐릭터만 2D 그림이다. D 가 그림을 바꾸면 파일만 바꾸면 된다.

## 5. 가로 화면 전환

- 앱 전체를 가로로 고정한다 (안드로이드 `screenOrientation`, iOS `UISupportedInterfaceOrientations`, Flutter `setPreferredOrientations`).
- 기존 화면은 세로 목록 구조라 그대로 두면 깨진다. 공통 원칙: 왼쪽 큰 영역에 그림(창밖·캐릭터), 오른쪽에 버튼·정보를 두는 2단 배치로 바꾼다.
- **B 파트 화면이라 B 와 함께 한다.** A 는 탐험 화면과 공통 레이아웃 틀을 먼저 만든다.
- PR #47 의 Flutter 판 차 안 뷰(`WindowView`)는 Unity 를 쓸 수 없는 상황(빌드 실패·저사양 기기)을 대비한 대체 화면으로 남긴다.

## 6. 품질 기준

| 항목 | 기준 |
| --- | --- |
| 프레임 | 중급 안드로이드 기기에서 60fps 목표, 최저 30fps |
| 메모리 | 탐험 화면 진입 시 추가 300MB 이하 (실측 후 조정) |
| 앱 용량 | Unity 포함 증가분 80MB 이하 (실측 후 조정) |
| 진입 시간 | 탐험 화면 첫 진입 3초 이내 |
| 멀미 | 카메라가 아이의 조작 없이 크게 움직이지 않는다. 급제동 연출도 카메라는 살짝만 흔든다 |

차량 앱 성능 기준(CPU 5%, RAM 400MB)은 **차 쪽 앱**에만 해당하므로 이 화면과 무관하다. 차량 앱은 바꾸지 않는다.

## 7. 테스트

- **Unity EditMode**: 메시지 파싱(버전·모르는 필드 무시), 캐릭터 상태 기계 전이, 청크 장면 전환 순서, 와이퍼 주기.
- **Unity PlayMode**: 캐릭터가 면 밖으로 떨어지지 않는다, 장면 변경 시 청크가 끊기지 않는다.
- **Flutter**: `WindowScene` → `scene` 메시지 인코딩, `jolt` 는 증가할 때만 한 번, 모은 캐릭터 목록 → `cast`.
- **실기 확인**: 에뮬레이터 + 실제 휴대폰에서 scene_tour 시나리오로 장면 전환·프레임·메모리 측정. 결과는 `docs/verification.md` 에 적는다.

## 8. 단계

| 단계 | 내용 | 끝났다는 기준 |
| --- | --- | --- |
| 0. 연동 검증 (spike) | Unity·Blender 설치, 빈 Unity 장면을 Flutter 앱에 넣어 에뮬레이터에서 띄우고 메시지 왕복 | 안드로이드에서 화면이 뜨고 `ready`·`scene` 이 오간다. **실패하면 Flame 2.5D 로 전환 검토** |
| 1. 차 안 + 둘러보기 | 차 내부 모델, 카메라 회전·레일 이동, 가로 고정 | 360도로 둘러볼 수 있다 |
| 2. 창밖 | 청크 스크롤, 장면 6종, 밤·비·터널, 와이퍼 | `scene` 메시지대로 바뀐다 |
| 3. 캐릭터 | 빌보드, 면 그래프, 행동 상태 기계, 차 신호 반응 | 돌아다니고 올라가고 창문에 붙는다 |
| 4. 물체 놀이 | 탭 반응, 물리 물체, 김 서린 창 그림 | 표 2.2 의 반응이 모두 동작 |
| 5. 앱 가로 개편 | 기존 화면 가로 레이아웃 (B 와 함께) | 모든 화면이 가로에서 깨지지 않는다 |
| 6. 다듬기 | 조명·소리·성능 측정·시연 동선 | 품질 기준 충족, PT 시연 리허설 |

## 9. 위험

| 위험 | 대응 |
| --- | --- |
| `flutter_unity_widget` 이 Unity 6 이나 최신 Flutter 와 안 맞을 수 있다 (추정, 0단계에서 확인) | 0단계에서 가장 먼저 확인. 안 되면 Unity 버전을 낮추거나 Flame 으로 |
| 빌드가 복잡해져 팀원 빌드가 깨진다 | Unity 내보내기 결과는 git 에 넣지 않고 스크립트 한 줄로 만든다. Unity 없이도 Flutter 가 빌드되도록 탐험 화면을 플래그로 분리 |
| 기존 화면 가로 개편이 B 일정과 겹친다 | 공통 2단 레이아웃 틀을 A 가 먼저 만들어 B 부담을 줄인다 |
| 스크립트로 만든 모델 퀄리티가 기대보다 낮다 | 1단계에서 차 내부 렌더를 먼저 보여 주고 방향을 확정한 뒤 나머지를 만든다 |
| 시연 기기 성능 부족 | 품질 설정 단계(그림자·파티클·청크 거리)를 둔다 |
