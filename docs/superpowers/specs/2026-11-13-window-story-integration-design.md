# 창밖 이야기 · 현재 모바일 화면 통합안

작성 2026-11-13 · 상태: 코드 구조 대조를 마친 설계 제안, 앱 구현 전

목표는 [이야기 기획](2026-11-13-window-story-learning-design.md)과 [8편 대사](../../window-story-dialogue.md)를 현재 차 안 화면에서 진행하는 것이다. 이번 작업 범위는 화면·입력·상태 충돌을 피하는 통합 설계이며 앱 코드는 변경하지 않는다.

## 1. 확인한 현재 화면과 충돌 지점

- `AppUi.BuildChrome`: 상단 상태·재료 HUD, 오른쪽 화면 이동 메뉴, 상단 중앙 알림.
- `AppUiViews.BuildCabin`: 왼쪽 위 친밀도·남은 시간, 하단 돌봄 버튼 5개. 글 입력과 자리 메뉴는 별도 오른쪽 서랍.
- 알이 없거나 부화한 상태에서는 `BuildCabinStart`가 하단에 높이 292 기준 단위의 시작 패널을 표시한다. 이야기 UI를 이 분기 아래에 추가하면 부화 후에는 보이지 않을 수 있다.
- `CritterDirector.Talk`: 장면 변경 대사와 35~65초 주기의 혼잣말·부탁이 별도로 존재한다. 기존 대사 문맥은 터널→밤→비→지역 순이며 새 이야기의 선택 규칙과 같지 않다.
- `AppUi.Render`: 상태 변경 시 `_content` 자식을 파괴하고 다시 만든다. 이 영역에 실험 애니메이션을 넣으면 주행 상태 갱신 때마다 다시 시작할 위험이 있다.
- `CameraRig.Locked`는 한 손가락 드래그 일부를 막지만 핀치·자이로·관성 모두를 막지는 않는다. 이야기 버튼 위에서 시작한 터치를 막는 것만으로는 충분하지 않다.
- `CabinEgg`는 알 드래그·문지르기, `TapInput`은 차 안 사물·캐릭터 입력을 별도로 처리한다.
- Dart는 일반 행동에 전역 `_pending/busy`와 직렬 큐를 사용한다. 대사 다음 버튼을 여기에 그대로 넣으면 앱 전체에 처리 중 상태를 반복 표시하게 된다.

## 2. 권장 화면: 차 안의 작은 이야기 모드

새 화면으로 이동하거나 기존 버튼 옆에 선택지를 더하지 않는다. 차 안 화면에서 **돌봄 조작 영역과 이야기 조작 영역을 교대로 사용**한다. 최신 통합안에서는 이전 기획의 오른쪽 선택 버튼 대신 하단 선택 버튼을 사용한다. 현재 오른쪽 탐색 메뉴를 보존하기 위한 변경이다.

### 평소

- 기존 돌봄 화면을 유지한다.
- 새 주제는 상단 콘텐츠 영역의 오른쪽, 고정 탐색 메뉴 왼쪽에 `이야기 · 바람 우편배` 초대 칩 하나로 표시한다. 왼쪽 친밀도와 중앙 오류 알림을 침범하지 않는다.
- 칩을 누르면 이야기 시작. 닫기 버튼은 해당 초대를 미룬다. 자동 말풍선이나 화면 전환은 하지 않는다.
- 공간이 좁거나 오류 알림이 있으면 제목을 줄여 책 아이콘 배지만 표시한다. 배지를 위해 새 하단 줄을 추가하지 않는다.

### 이야기 시작 후

```text
┌─────────────────────────────────────────────────────┐
│ 기존 상단 HUD · 연결 상태                            │
│ 알 상태·남은 시간       바람 우편배  [돌봄으로] │ 차 안 │
│                                               │ 시설 │
│    현재 차 안 배경 + 화면 속 작은 실험 무대     │ 친구 │
│    친구 초상/반응 + 돛단배                     │ 가방 │
│                                               │ 설정 │
│ “뒤에서 바람이 불어. 돛을 어떻게 할까?”               │
│         [ 돛 펼치기 ]       [ 돛 접기 ]                │
└─────────────────────────────────────────────────────┘
```

- 기존 하단 돌봄 버튼 또는 알 시작 패널을 이야기 도크로 대체한다. 두 도크를 동시에 띄우지 않는다.
- 하단 도크는 대사 최대 2줄과 버튼 2개로 구성한다. 선택 없는 노드에는 다음 버튼 하나만 둔다. 안전 영역 높이의 약 25~30%를 출발점으로 기기에서 확인한다.
- 가운데 실험 무대는 별도 2D 레이어로 표현한다. 실제 창밖은 계속 갱신하고, 무대에 `이야기 속 실험`을 표시한다. 배경 종류를 바꿔 실험 결과를 흉내 내지 않는다.
- 친구 초상을 도크에 두어 차 안 캐릭터가 다른 곳으로 움직여도 대사를 읽을 수 있게 한다. 안내 캐릭터가 없으면 길싹이 안내 배지로 대체한다.
- 알 상태·남은 시간과 `[돌봄으로]`는 항상 보인다. 전환하면 이야기를 보관하고 돌봄 버튼을 복구한다. 이어 하기는 아이가 직접 선택한다.
- 오른쪽 다른 화면으로 이동하면 이야기를 보관하고 정상 이동한다. Android 뒤로 가기는 이야기 접기 → 기존 홈 이동 순으로 처리한다.

## 3. 활동 우선순위와 알 돌봄 보호

이야기를 위한 전역 게임 정지나 친밀도·부화 시간 변경은 하지 않는다. 숨겨진 돌봄 의무 때문에 알을 놓치지 않게 시작 조건과 양보 조건을 둔다.

| 상황 | 이야기 처리 |
| --- | --- |
| 사진 촬영·음성 입력·권한창·확인창·자리/글 서랍·알 드래그 진행 중 | 초대는 보관, 시작 불가. 사용자 행동 종료 후 표시 |
| `photoRequired`, 부화 전환, 실패·돌봄 종료 | 즉시 보관하고 기존 UI/연출에 양보. 자동 재개 금지 |
| 돌봄 남은 시간 120초 이하 | 자동 초대와 새 이야기 시작을 보류. 진행 중이면 보관하고 돌봄으로 복귀 |
| 활성 알의 남은 시간을 신뢰할 수 없음 | 자동 초대 보류. 차 안의 기존 돌봄 동작 우선 |
| 알 없음·안정된 부화 후 | 이야기 가능. 부화 직후 안내가 끝나기 전에는 초대 보류 |
| 홈·캠프·도감으로 이동, 백그라운드 전환 | 노드 보관, 연출·대사 중단. 복귀 후 이어 하기 제공 |
| 연결 단절 | 진행 중 로컬 이야기는 유지 가능. 새 실제 환경 초대 중단 |
| 저장 실패 | 카드 도크에서만 재시도 표시. 전체 앱을 처리 중으로 잠그지 않음 |

120초는 초기 제안값으로 실제 돌봄 시간과 사용자 테스트 후 조정한다. 구현 시 확인한 거리 기반 돌봄은 남은 거리 `(hatchAtM × (1 - progress))`가 `max(500m, 현재 속도로 120초 이동 거리)`보다 클 때 이야기를 허용한다. 이는 돌봄 복귀 여유를 위한 추정이며 실제 부화 판정은 변경하지 않는다. 문자열 `remainingLabel`을 파싱하지 않고 Dart의 실제 남은 시간·phase로 판단한다. 사진 요구 등이 실행 중 발생하면 클릭 결과를 적용하기 직전에도 다시 확인한다. 이미 수락된 노드는 저장하되 양보 상태를 뒤늦은 응답으로 해제하지 않는다.

## 4. 대사·입력·렌더링 충돌 방지

### 대사는 한 곳만 사용

- 이야기 시작 시 기존 일반 말풍선을 닫고 scene/idle/request/sleep_talk 출력을 보류한다. `CritterDirector` 전체를 중지해서 부화 연출까지 멈추면 안 된다.
- 부화 등 중요 이벤트는 이야기보다 우선한다. 복귀 시 보류한 잡담을 몰아서 재생하지 않고 타이머를 새로 잡는다.
- 초대 칩만 있는 상태는 기존 잡담과 공존 가능하다. 이야기 대사는 초대 칩을 누른 뒤에만 시작한다.

### 입력 소유권은 하나

- `care/story/native/modal` 활동 상태를 명시하고, 이야기 중 `CabinEgg` 제스처와 `TapInput` 월드 탭을 차단한다. Unity뿐 아니라 Dart에서도 이야기 중 들어온 낡은 돌봄 intent를 거절한다.
- 시작은 기존 포인터가 모두 해제된 다음 확정한다. 알 제스처가 진행 중이면 새 모드에 진입하지 않는다. 모드 전환·이탈 시 드래그 상태를 해제한다.
- 이야기 중 카메라 드래그·핀치·자이로·관성·자동 시선 이동을 제한한다. `Rig.Locked` 한 값만 덮어쓰지 않고 활동별 입력 차단 소유권을 둔다.
- 이전 설정을 존중하고 종료 후 복구한다. 다른 화면·모달이 아직 입력을 소유하면 이야기 종료만으로 입력을 다시 켜지 않는다.
- 전체 화면 투명 패널로 UI까지 막지 않는다. 세계 입력은 활동 상태로 차단하고, 도크·무대의 필요한 영역만 UI raycast를 받는다. 탐색 메뉴와 돌봄 복귀는 계속 접근 가능하다.

### 주행 갱신으로 이야기 화면이 초기화되지 않게

- 지속되는 `StoryOverlay`를 `_content` 밖의 동일 safe-area 아래에 만든다. `AppUi.Render()`의 매번 파괴하는 대상에서 제외한다.
- `instanceId/nodeId/storyRevision`이 바뀔 때만 대사·실험 상태를 갱신한다. 속도·재료·알 쿨다운 갱신은 실험을 다시 시작하지 않는다.
- 노드 연출을 복귀하면 저장된 결과 그림 또는 해당 노드 시작부터 재생한다. 화면 표시 콜백은 카드 보상·친밀도 변경을 수행하지 않는다.

## 5. 배경과 대사의 연결

기존 차량 판정은 그대로 사용한다. 실제 의미를 새로 판정하지 않고 **현재 화면에 표시할 안정화 결과**로 주제를 선택한다.

1. `UnityAppController`에서 `WindowScene`과 안정화 결과를 한 번 계산해 Unity 장면·StoryDirector가 같은 값을 받는다. 이야기용 타이머가 기존 안정화기를 별도로 진행시키지 않게 한다.
2. 키는 `kind/night/highway/rain 유무`. 속도 수치·와이퍼 1→2 변경은 새 주제가 아니다.
3. 지역 4초·터널 즉시라는 화면 전환 규칙은 유지. 밤·비·고속도로 주제는 이야기 초대에 한해 5초 유지 후 준비한다. 화면 효과 반영은 늦추지 않는다.
4. 동시에 여러 새 조건이 오면 터널 → 새 비 → 새 밤 → 새 지역 → 고속도로 순. 기존 잡담 문맥 선택 함수를 재사용하지 않는다.
5. 대기 후보는 최신 하나, 진행 중 이야기는 하나. 배경이 바뀌어도 현재 실험과 선택 상태는 유지한다.
6. 종료 후 다음 이야기는 자동 시작하지 않는다. 현재 조건·90초 초대 간격·돌봄 우선권을 다시 검사한다.
7. 실제 차량 시간과 샘플 신호를 혼동하지 않게 체험 모드 표시는 유지한다. 연결 첫 스냅샷에도 초대 가능한 주제를 하나 준비하되 기본 초기 road를 실제 도착 이벤트로 취급하지 않는다.

## 6. 코드 변경 단위 제안

| 영역 | 최소 변경 |
| --- | --- |
| `phone/assets/data/window_stories_ko.json` 신규 | 대사집을 검수 메타데이터·노드·A/B 행동·결말이 있는 정적 팩으로 변환 |
| Dart `StoryDirector` 신규 | 환경 후보, 진행 상태, 중복 처리, 돌봄 양보, 로컬 저장 담당 |
| `UnityAppController` | 동일 scene 공유, story 스냅샷·명시적 intent 허용 목록·phase 검사 추가 |
| `AppSession` 및 DTO | 선택적 story 상태와 storyStart/Choose/Pause/Resume/Save intent 추가. story가 없으면 기존 화면 그대로 |
| `AppUi` / `AppUiViews` | 초대 칩, 기존 도크 전환, 서랍·확인창 상태 조정, 알 없음 분기에서도 이야기 가능 |
| 신규 `StoryOverlay` | 지속되는 말풍선·두 버튼·2D 실험 무대. 선택 즉시 해당 버튼만 잠금 |
| `CritterDirector.Talk`, `TapInput`, `CabinEgg`, `CameraRig` | 일반 대사와 입력의 활동 소유권 확인 |
| `AppSession` 뒤로 가기 | 먼저 이야기를 보관·접고, 다음 뒤로 가기부터 기존 처리 |

선택 intent에는 `instanceId/nodeId/actionId/storyRevision/requestId`를 넣는다. Dart가 현재 노드에서 가능한 행동인지 확인하고 결과 스냅샷을 보낸다. 전역 app revision은 주행 중 자주 바뀌므로 선택 검증에 쓰지 않는다. story 전용 revision을 사용한다.

일반 게임 행동의 전역 `_pending`에 모든 이야기 버튼을 넣지 않는다. 이야기 전용 직렬 처리와 `story.pending`을 두고, 저장 중에는 이야기 관련 행동만 막는다. 캠프·부화·재료 판정은 기존 제어기가 계속 담당한다.

## 7. 구현·검증 순서

1. 바다 한 편 + 2D 배/돛 실험 + 도크 전환으로 입력·렌더링 구조 확인.
2. 돌봄·사진·부화 우선권, 뒤로 가기·탐색·백그라운드 복귀 확인.
3. 안정화 scene 연결과 연속 배경 전환·알림 억제 확인.
4. 카드 저장·실패 재시도 후 나머지 7편 연동. 실시간 AI·음성은 후속.

필수 통과 조건:

- 이야기 버튼을 눌러도 알 친밀도·위치·캐릭터 소지품·카메라가 변하지 않는다.
- 초당 반복되는 차량 갱신 동안 실험·대사·선택 단계가 초기화되지 않는다.
- 사진 요구/부화/남은 시간 임계점이 선택 응답과 겹쳐도 중요 흐름이 우선한다.
- 대사창은 하나만 보이며 알 없음·부화 후에도 이야기 도크가 정상 표시된다.
- 빠른 연타·이전 노드 입력·중복 응답으로 두 단계 진행하거나 카드를 중복 저장하지 않는다.
- 앱 백그라운드·차 안 이탈·뒤로 가기 후 입력 잠금이 남지 않는다. 복귀 때 멈춘 자리부터 이어 갈 수 있다.
