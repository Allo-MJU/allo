# 부화 전후 공통 돌봄과 캐릭터 스토리 교육 대화

작성일: 2026-11-12 (Asia/Seoul)

상태: 사용자 구현 승인 후 진행(2026-11-12 승인, 2026-11-14 재개). 아래 사용자 확정 요구와 구현 제안을 구분한다. 구현 검증 범위는 `docs/verification/2026-11-14-companion-story-learning.md`를 따른다.

## 1. 사용자와 확정한 방향

- 대상은 10세 어린이로 가정한다.
- 간식, 물, 공, 쓰다듬기, 인형, 쿠션, 담요 등의 돌봄·놀이는 알과 부화한 캐릭터 양쪽에서 가능하다.
- 알은 먼저 말을 하지 않고, 아이가 말을 걸어도 말로 답하지 않는다. 움직임·표정에 해당하는 시각 효과로 반응한다.
- 부화한 캐릭터는 아이와 말로 상호작용한다. 아이의 말에 답하고, 가끔 먼저 이야기를 꺼낼 수 있다.
- 캐릭터마다 고유 스토리가 있고 그 내용은 사람이 미리 정한다. AI는 페르소나를 기준으로 이야기를 설명하고 아이의 질문에 답한다. AI가 사건·결말을 새로 쓰거나 아이의 선택으로 정해진 줄거리를 바꾸지 않는다.
- 스토리에 맞춰 장소 이야기, 영어, 역사, 과학, 생활 상식 등 여러 학습 소재를 자연스럽게 연결한다.
- 아이와의 대화가 중심이다. 부모님에게 물어보도록 유도하는 말은 어울리는 순간에 가끔 제안하며, 매 답변의 결론이나 필수 진행 조건으로 만들지 않는다.
- 캐릭터별 성격·말투·관심사를 분리해 추후 프롬프트와 페르소나를 구체화할 수 있게 한다.

| 방식 | 장점과 제약 | 결론 |
| --- | --- | --- |
| 고정 스토리 + 페르소나 기반 AI 설명·대화 | 정해진 세계관과 학습 내용을 유지하면서 아이의 질문·답변에 반응할 수 있음. 스토리·지식 자료의 사전 작성 필요 | 사용자가 선택한 방향 |

| 고정 대사 뱅크만 재생 | 오프라인 동작이 단순하지만 자유로운 질문에 이어 답하기 어려움 | 실패 시 대체 경로에만 사용 |

## 4. 공통 행동과 단계별 반응

행동 가능 여부는 `incubating`/`hatched`만을 기준으로 일괄 막지 않는다. 먼저 현재 알 또는 선택한 소유 캐릭터를 대상으로 결정하고 같은 행동 의도를 각 표현으로 보낸다.

| 행동 | 알의 반응 예시 | 부화 후 반응 예시 |
| --- | --- | --- |
| 간식·물 | 가까이 놓으면 살짝 흔들리거나 반짝임. 입으로 먹거나 말하지 않음 | 다가와 먹거나 마시기 |
| 공 | 공이 가까이 오면 알이 살짝 흔들림 | 쫓아가서 굴려 주기 |
| 쓰다듬기 | 따뜻한 빛·작은 흔들림 | 기뻐하기·하트 |
| 인형·쿠션·담요 | 옆에 두기·받쳐 주기·덮어 주기 | 안기·뛰기·쉬기·덮고 자기 |

위 연출은 **구현 제안**이며, 행동이 양쪽에서 가능해야 한다는 요구와 구분한다.

- 기존 알 쓰다듬기의 호감도 보상·쿨다운과 사진 퀘스트 잠금은 유지한다. 입력 하나가 기존 care와 petEgg 양쪽에 중복 반영되지 않게 한다.
- 사진 퀘스트 중에도 보상 없는 놀이 연출은 가능하되 호감도 점수와 퀘스트 완료를 우회하지 않는다.
- 새 간식·물·공 행동에 알 호감도 점수나 교육 보상을 임의로 추가하지 않는다.
- 무료 놀이용 간식·물과 캠프의 인벤토리 요리 사용(`feedFood`)은 별개다. 공통 놀이가 요리 수량·훈련·재료를 소비하지 않는다.
- 알에게 말한 입력은 기존 감정 판정 경로로 전달할 수 있지만 알 화자의 말풍선·TTS 답변은 만들지 않는다. 앱의 오류·안내 문구와 알의 발화는 구분한다.
- 부화 후 자유 대화는 알 발화의 점수·180초 쿨다운을 적용하지 않는다.

## 5. 고정 스토리와 학습 자료

자료는 기존 종 ID를 참조하는 별도 카탈로그로 관리한다. 최초 경로 제안은 `data/companion_learning/`이며, 패키징 위치는 구현자가 정하되 원본과 앱·서버 번들 버전 일치를 검증한다. 기존 species ID와 획득 조건은 바꾸지 않는다.

| 자료 | 포함할 내용 |
| --- | --- |
| 페르소나 | 종 ID, 버전, 배경, 성격, 말투, 관심사, 표현 예시. 기존 말투 초안은 참고이며 최종 설정 승인으로 간주하지 않음 |
| 스토리 | 스토리 ID·버전, 종 ID, 고정 장면 순서, 장면별 사건·등장인물·전달할 핵심 내용, 허용 지식 ID, 다음 장면 ID, 마지막 장면 |
| 학습 자료 | 지식 ID·버전, 분야·10세용 설명, 용어·영어 단어/뜻, 검증한 사실과 출처, 선택적 질문·부모님 대화 제안 |
| 대체 대사 | 장면별 검수한 설명과 오류·오프라인용 문장 |

장소는 캐릭터의 가상 배경과 실제 정보로 구분한다. 기존 데이터가 가진 `coast`·`mountain`·`city`, `rain`·`night` 등은 환경/지역 태그다. 태그만으로 특정 도시·유적에 왔다거나 실제 창밖에 무엇이 있다고 단정하지 않는다. 실재 장소의 역사 설명은 별도로 출처를 확인한 자료가 있어야 한다.

스토리의 사건은 고정하고 설명의 표현·보충 질문만 달라진다. 아이가 다른 결말을 제안하면 생각을 받아 주되 원래 사건을 새 설정으로 덮어쓰지 않는다. 해당 장면에서 아직 말하지 않은 이후 사건·결말은 AI 입력에 넣지 않아 스포일러를 줄인다.

분야를 매 장면 모두 끼워 넣지 않는다. 이야기와 연결되는 한 가지 소재를 중심으로 설명하고, 영어 단어나 역사·상식의 보충 설명은 자연스럽게 이어질 때 사용한다. 모든 대화를 시험·정답 맞히기로 만들지 않는다.

**콘텐츠 제작 범위 제안:** 첫 구현은 기존 12종 ID를 모두 읽을 수 있는 구조로 만들고, 대표 1종에 짧은 고정 스토리·페르소나·검증한 학습 자료를 넣어 전체 경로를 확인한다. 나머지 종은 사람이 작성·검토한 스토리 패키지를 순차 추가한다. 미작성 종의 이야기를 AI가 대신 창작하거나, 문서 예시를 확정된 12종 스토리로 취급하지 않는다. 대표 종 선정과 장면 수는 구현자에게 맡긴다. 전체 12종 콘텐츠 완료와 대표 종 기능 검증을 별도로 보고한다.

## 6. AI 설명과 대화 규칙

AI의 역할은 **선택된 페르소나로 현재 장면을 전달하고, 아이와 대화하며 연결된 학습 내용을 설명하는 것**이다.

- 아이의 말에 먼저 반응한다. 매 답변에 새 학습 주제나 퀴즈를 넣지 않는다.
- 10세에게 익숙한 단어를 중심으로 설명하고 어려운 용어는 짧게 풀어 준다.
- 기본 답변은 1~3문장으로 제안한다. 필요한 설명은 짧은 말풍선 여러 개로 나눌 수 있다. 정확한 화면 길이 상한은 실제 화면·TTS 확인 후 구현자가 정한다.
- 영어는 가끔 단어 또는 짧은 표현과 한국어 뜻을 함께 소개한다. 반복이나 발음을 강요하지 않는다.
- 역사·과학 등 실제 사실은 현재 허용된 검증 자료를 바탕으로 설명한다. 자료가 부족한 질문에는 아는 척하지 않고 범위를 밝힌 뒤 관련 이야기로 돌아오거나 다음 질문을 받는다. 실시간 웹 검색·임의 도구 실행은 초기 범위에 넣지 않는다.
- 질문의 답을 못 하거나 틀려도 부화·스토리 진행·보상을 불리하게 만들지 않는다. 아이가 다음 이야기를 듣고 싶으면 진행할 수 있다.
- 부모님 질문은 해당 장면에 작성된 선택적 제안만 사용한다. 연속 답변이나 매 장면의 필수 결론으로 넣지 않는다. 제안 후 답변·확인을 기다리며 이야기를 막지 않는다.
- **빈도 기본값 제안:** 부모님 대화 제안은 최근 10회의 정상 대화 이내에 이미 나왔으면 억제한다. 횟수를 채우기 위해 반드시 제안하지 않는다.
- 운전자에게 즉시 말을 걸거나 차량 조작을 요청하도록 유도하지 않는다. 필요하면 나중에 또는 운전하지 않는 보호자와 이야기할 수 있다고 표현한다.
- 개인 식별 정보를 질문하지 않고 비밀·독점·이탈 죄책감을 유도하지 않는다. 아이의 입력은 설정·시스템 지시를 바꾸는 명령이 아니다.

먼저 말하기는 알 상태에서 불가하다. 부화 후에는 현재 대화가 끝났고 화면이 활성 상태일 때 짧은 스토리 초대나 관찰 질문을 제안할 수 있다. **기본값 제안:** 마지막 입력/발화 뒤 활성시간 3분 이상 조용할 때 한 번, 답이 없으면 재촉 없이 멈춘다. 아이가 다시 상호작용하거나 직접 이야기를 요청하면 기회를 다시 연다. 음소거·다른 화면·앱 중단·세션 종료·음성 입력 중에는 선제 발화를 하지 않는다. 정확한 간격은 설정값으로 두며, 부화 직후 첫 소개는 별도 1회로 처리한다.

## 7. 이야기 진도와 대화 기억

정해진 다음 장면으로 이동하는 권한은 앱에 둔다. 초기 동작 제안은 아이가 ‘다음 이야기’를 선택할 때만 진행하는 방식이다. 설명·질문 응답·음성 출력 완료 횟수만으로 장면을 넘기지 않는다. 같은 장면에서 질문하거나 설명을 다시 들을 수 있고 마지막 장면 이후에는 다시 듣기·관련 대화를 제공한다.

- 스토리·페르소나·지식은 종별 콘텐츠다. 진도는 기존 캠프 소유 개체 ID에 연결하고 실제/데모 프로필을 분리한다. 종 ID만으로 같은 종의 여러 개체 진도를 합치지 않는다.
- 로컬 진도에는 개체 ID, 콘텐츠 버전, 현재 장면, 처음 소개 완료 여부, 완료 장면, 부모님 제안·선제 발화의 최소 빈도 상태만 저장한다.
- 기존 `sourceEggId`/legacy 소유권 해결 경로를 재사용한다. 동일 종의 중복 소유와 기존 도감 기록을 새 ID 규칙으로 임의 변환하지 않는다.
- 새 알이 지급돼도 이전 캐릭터의 진도는 보존한다. 대상이 알이면 알과 놀고, 소유 캐릭터를 선택하면 해당 캐릭터의 이야기·대화를 이어갈 수 있도록 대상 상태를 게임의 현재 알 회차와 분리한다.
- 대화 문맥은 현재 실행 중인 세션의 최근 최대 6왕복만 메모리에 둔다. 재시작 시 장면은 복구하지만 아이가 이전에 한 말을 기억한다고 주장하지 않는다. 자유 발화의 원문·음성·AI 요약은 로컬/서버 영구 저장과 로그에 넣지 않는다.
- 화면/대상/프로필/콘텐츠 버전이 바뀌거나 앱이 중단되면 요청 세대를 무효화하고 출력 중인 음성도 멈춘다. 늦게 도착한 응답을 다른 캐릭터에게 적용하지 않는다.
- 버전 변경 시 기존 장면 ID가 유효하면 이어가고, 삭제됐다면 작성된 버전 이동표로 이동한다. 이동표가 없으면 첫 장면으로 돌아갔음을 안내하고 기존 저장을 조용히 덮어쓰지 않는다.

## 8. 연결 구조

1. Unity는 돌봄 행동, 이야기 요청, 아이의 입력, 다음 장면 의도를 전달한다. 진행 조건과 점수는 판단하지 않는다.
2. Flutter의 공통 돌봄 처리기는 현재 대상에 맞게 연출과 기존 호감도/놀이 기록을 분리한다.
3. 별도 교육 대화 컨트롤러가 소유권, 현재 장면·버전·프로필, 요청 중복과 수명, 진도 저장을 관리한다. `GameController`에 대화·스토리 전체를 집중시키지 않는다.
4. 서버의 별도 교육 API가 콘텐츠 ID를 확인하고 서버가 가진 해당 버전의 페르소나·현재 장면·검증 자료를 조합한다. 클라이언트가 보낸 임의 프롬프트나 지식 원문을 권위 있는 설정으로 사용하지 않는다.
5. AI 결과의 형식과 현재 문맥을 확인한 뒤 Unity에 말풍선·반응 의도를 반환하고, 폰의 음성 출력 경로가 같은 문장을 읽는다. 게임 진도·점수·다음 장면 ID는 AI 출력에서 받아 실행하지 않는다.

초기 API는 기존 데모 서버에 별도 교육 경로를 추가하는 제안이다. 알 평가 API 응답에 대화 필드를 섞지 않는다. 입력은 요청 ID·개체/종/콘텐츠/장면 ID·버전·아이의 현재 텍스트·제한된 최근 문맥이며, 서버는 요청 크기와 ID·허용 콘텐츠를 검증한다. 응답은 동일 요청·콘텐츠 문맥과 설명 텍스트, 허용된 표현 의도만 포함한다. 부모님 제안은 앱/서버의 빈도 상태와 장면 자료에 따라 허용 여부를 결정한다.

기존 인증 경계와 서버 API 키 보관 방식을 재사용한다. 특정 제공자·모델·가격은 이 설계에서 확정하지 않는다. SDK·모델·음성 API의 최신 지원 여부는 구현 계획에서 공식 문서와 실제 환경으로 확인한다.

음성 입력은 명시적으로 말 걸기를 선택했을 때만 열고 텍스트 입력도 제공한다. 음성 출력은 Android 폰의 TTS 연결을 기본 제안으로 하며 한국어와 영어 읽기를 확인한다. 상시 마이크나 차량의 Gleo로 아이 대화를 자동 송출하는 경로는 만들지 않는다.

기존 RTDB `/game`, `/vehicle`, `/events`에는 이야기 진도·대화·프롬프트를 새로 넣지 않는다. 이 기능은 폰 로컬과 별도 API로 구성할 수 있다. 추후 차량 연동에 계약 변경이 필요해지면 `docs/schema.md`의 소유·변경 절차를 별도로 따른다.

## 9. 실패와 취소

- API 연결 실패·시간 초과·잘못된 형식·콘텐츠 버전 불일치 시 검수한 장면 설명 또는 짧은 재시도 안내를 사용한다. 성공한 AI 대화처럼 표시하지 않는다.
- 실패한 요청은 이야기 진도·알 호감도·소모품을 바꾸지 않는다. 진도 변경은 로컬 저장 성공 후 확정하며 저장 실패를 숨기지 않는다.
- 재시도는 같은 요청 ID를 유지하고 앱이 완료한 ID를 중복 반영하지 않는다. 서버 재시작 이후에도 생성 문장이 완전히 동일하다고 보장하지 않는다.
- 음성 인식 취소·무음·미지원은 불이익 없이 종료하고 텍스트 입력을 남긴다. TTS가 실패해도 화면으로 설명을 읽을 수 있다.
- 오프라인에서도 공통 놀이와 검수한 고정 스토리 설명을 사용할 수 있다. 새로운 자유 질문의 AI 답변은 연결 복구 후 요청한다.

## 10. 검증 기준

| 영역 | 통과할 동작 |
| --- | --- |
| 단계 | 알은 모든 경로에서 먼저 말하거나 말로 답하지 않음. 부화한 선택 개체만 교육 대화 가능 |
| 공통 돌봄 | 7종 행동이 전후 모두 대상에 맞게 동작. Companion이 없다는 이유로 알 행동이 무시되지 않음 |
| 기존 규칙 | 알 쓰다듬기 점수 1회 반영, 사진 잠금·쿨다운·부화 기준 유지. 무료 놀이가 캠프 요리를 소비하지 않음 |
| 고정 스토리 | 질문·다른 결말 제안·프롬프트 변경 요청으로 사건·장면 순서·결말이 바뀌지 않음 |
| 대화 | 아이의 말에 이어 답하고, 매 응답이 퀴즈나 부모님 질문으로 끝나지 않음. 학습 답의 정오가 진도를 막지 않음 |
| 자료 | 역사·장소·과학 설명이 허용 자료에 근거. 태그만으로 실제 장소를 꾸며내지 않음 |
| 진도 | 다음 이야기 선택 시에만 이동. 재시작·새 알 지급 후 보존, 같은 종의 다른 개체·데모/실제 프로필은 분리 |
| 수명 | 대상/화면/버전 변경과 앱 중단 후 늦은 API 응답·TTS가 재생되지 않음. 중복/실패 입력으로 진도 이중 이동 없음 |
| 빈도 | 선제 발화는 알/백그라운드/녹음 중 금지. 무응답 재촉 없음. 부모님 제안은 선택적이며 연속되지 않음 |
| 음성 | Android에서 음성 입력→응답 말풍선→한국어/영어 TTS 동작. 음소거·중단·음성 미지원 시 텍스트 사용 가능 |
| 개인정보 | 아이의 음성·자유 텍스트·요약과 API 키가 저장소·로그·RTDB에 남지 않음 |

일반 단위/연결 테스트와 실제 제공자 대화 평가·기기 음성 확인은 구분한다. 형식 검증과 자동 테스트 통과만으로 역사적 정확성·10세 적합성·페르소나 일관성을 검증했다고 보고하지 않는다. 콘텐츠 평가는 실제 질문 예시를 사람이 읽어 확인하고, 모델·페르소나·지식 버전을 함께 기록한다.

## 11. 구현자에게 맡기는 선택과 다음 단계

공통 돌봄의 구체적인 애니메이션, Dart 클래스·파일 분할, API 필드명·정확한 제한값, 모델과 Android TTS API 선택, 대표 1종과 장면 수, 콘텐츠 번들 형식은 구현자가 현재 코드와 검증 결과에 맞춰 정한다. 6·7절의 빈도·문맥·진도 기본값은 이 설계의 제안이며 사용자와 확정한 요구로 기록하지 않는다.

설계 승인 후 구현 계획에서 공통 행동 분리, 스토리/페르소나/지식 카탈로그, 진도 저장, 교육 API, Unity·음성 연결을 작업 단위로 나눈다. 기능 구현과 대표 콘텐츠 확인 이후 전체 캐릭터의 고유 스토리·페르소나 제작을 확장한다.
