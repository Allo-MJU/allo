# ALLO 창밖 이야기 탐험 기획

작성: 2026-11-13 · 상태: 기획 제안, 구현 전

## 1. 목표와 범위

**차창 밖 배경이 바뀌면 동행 친구가 작은 사건을 발견하고, 아이가 버튼으로 이야기를 움직이며 원리 하나를 발견한다.**

교육 내용을 설명하는 별도 교실 대신 기존 차 안 탐험에 45~90초짜리 이야기를 얹는다. 아이의 역할은 답을 맞히는 학생보다 친구와 함께 실험하는 탐험가다. 버튼을 누른 결과가 장면에 보여야 한다.

- 이번 산출물: 모바일 플레이 흐름, 주제·대본, 화면, 생성 규칙, 연동 및 검증 계획. 앱 구현이나 기존 계약 변경은 포함하지 않는다.
- 우선 난이도: 기존 영어 대화 시제품의 10~12세를 기준으로 한 원인 예측·비교. 저학년용은 관찰·선택 중심의 쉬운 모드로 확장한다. 프로젝트 전체 대상 연령을 재정의하지 않는다.
- 신규 이야기 모드는 한국어 버튼·짧은 한국어 대사를 기본 제안으로 한다. 영어 자유 대화는 그대로 별도 기능이며 영어 이야기 팩은 후속이다. 이 문서의 언어·난이도는 신규 모드의 제안이다.
- 완료 조건: 기존 환경 신호로 각 이야기를 시작할 수 있고, 모든 선택의 결과와 교육 포인트가 명확하며, 배경 전환·중단·오프라인에서도 흐름이 정의되어 있다.
- 검증: 코드·문서의 실제 구조와 대조하고, 대표 대본과 예외 상황을 추적한다. 재미·학습 효과는 구현 후 사용자 관찰로 확인한다.

## 2. 현재 프로젝트에 연결하는 방법

| 확인한 현재 구조 | 기획에 반영 |
| --- | --- |
| 최신 Unity phone 설계: 가로 Unity 화면, Flutter는 상태·판정 담당 | 차 안 화면에 Unity 말풍선과 선택 버튼을 추가하고 Dart가 이야기 상태를 관리 |
| `WindowScene`: road/coast/mountain/city/tunnel, 별도 night/highway/rainLevel | 기본 지역과 날씨·시간을 조합해 주제 선택. 고속도로·밤·비를 별도 지역으로 오인하지 않음 |
| `SceneStabilizer`: 지역 4초 유지, 터널 즉시 전환 | 안정화된 장면을 공유하고, 이야기 자체의 중복·빈도 제어를 추가 |
| 환경 태그는 있고 카메라 사물 인식은 없음 | “바다 이야기 해 볼까?”는 가능. “저기 실제 고래가 있어!”라는 관찰 주장은 불가 |
| 동행·알·캠프·도감과 12종 캐릭터 존재 | 현재 친구가 안내하고 발견 카드를 별도 여행 노트에 저장 |
| 영어 자유 대화는 별도 로컬 시제품 | 기존 채팅 API가 이야기 분기·한국어 검수·보상을 지원한다고 가정하지 않음 |

## 3. 핵심 게임 루프

1. **발견**: 배경 변화가 확정되면 친구가 창 쪽을 보고 작은 주제 배지를 띄운다. “바다야! 작은 배를 움직여 볼까?”
2. **초대**: `[같이 해 보기] [나중에]`. 자동으로 긴 설명을 시작하지 않는다.
3. **사건**: 화면 속 작은 배·씨앗·빛 장난감에 해결할 일이 생긴다. 대사 한 번에 개념 하나만 제시한다.
4. **선택**: 아이가 2개의 행동 버튼 중 하나를 누른다. 예측 → 조작 → 결과 관찰을 2~3회 반복한다.
5. **발견**: 친구가 방금 본 결과를 한 문장으로 연결한다. `[다른 방법도]`로 결과를 비교할 수 있다.
6. **기록**: 발견 카드 1장에 내가 한 행동·관찰한 결과·원리 한 줄을 남긴다. `[돌아가기] [더 궁금해]`로 마무리한다.

재미의 핵심은 **버튼에 따라 실제로 달라지는 장난감 실험**, 캐릭터의 예상 밖 반응, 선택 결과가 남는 수집이다. 오답 표시·점수 경쟁·연타·시간제한은 기본 루프에 넣지 않는다. 틀린 예상도 결과를 확인하는 유효한 탐험이다.

## 4. 대표 플레이: 바닷바람 우편배

교육 목표: 바람이 돛에 힘을 주어 배를 움직일 수 있음을 비교한다. 현실 배의 항해를 완전히 재현하는 물리 시뮬레이션은 아니다.

| 단계 | 가이드 대사 | 버튼 | 즉시 보이는 결과 |
| --- | --- | --- | --- |
| 초대 | “바다 이야기야! 작은 배에 편지를 실어 볼까?” | 같이 해 보기 / 나중에 | 시작하면 창가에 장난감 바다와 우편배 등장 |
| 예상 | “같은 바람이 불어. 돛을 어떻게 할까?” | 돛 펼치기 / 돛 접기 | 펼치면 돛이 부풀고 더 멀리 이동. 접으면 짧게 이동 |
| 비교 | “이번에는 반대로 해 보자!” | 돛 접기 또는 돛 펼치기 / 결과 다시 보기 | 같은 바람·같은 시간으로 두 결과를 나란히 표시 |
| 발견 | “이 실험에선 돛을 펼친 배가 더 멀리 갔어.” | 왜 그럴까? / 편지 보내기 | 설명을 고르면 “바람이 돛을 밀어 배를 움직였어.” |
| 결말 | “편지가 도착했어. 우리도 바람의 힘을 찾았네!” | 카드 담기 / 한 번 더 | 바람 카드 저장. 반복해도 같은 카드가 중복 지급되지는 않음 |

두 선택 모두 결말에 도달한다. 접은 돛을 택해도 실패 화면 대신 비교 실험을 거친다. 조작은 모두 게임 속 장난감에 적용된다. 예시 대사는 콘텐츠 검수 전 초안이다.

발견 카드 예시: **바람 우편배** / “돛을 펼쳤어 → 같은 바람에서 더 멀리 갔어” / “바람은 물체를 움직이는 힘을 줄 수 있어.” 정차 후 대화거리: “바람으로 움직이는 다른 물건도 있을까?”

## 5. 배경별 이야기 팩

| 배경·조건 | 작은 사건과 가이드 연출 | 버튼 놀이 | 발견할 개념 |
| --- | --- | --- | --- |
| 기본 도로 | 길싹이의 씨앗 여행 가방 | 날개 달기 / 둥글게 만들기 → 같은 바람에서 비교 | 씨앗 모양과 이동 방식 |
| 바다 | 물결지기의 우편배 | 돛 펼치기 / 접기 | 바람의 힘 |
| 산 | 산정령의 빗물 길 찾기 | 풀 있는 흙 / 맨흙에 비 내려 보기 | 땅의 덮개와 흙이 씻겨 가는 정도 |
| 도시 | 다리뛰기의 장난감 다리 | 받침 추가 / 그대로 시험 | 구조를 지탱하는 받침 |
| 터널 | 터널나방의 그림자 극장 | 빛 가까이 / 멀리 | 광원·물체·스크린 위치와 그림자 크기 |
| 비 | 웅덩이삐약의 물방울 길 | 흙길 / 포장길에 같은 양의 비 | 스며드는 물과 표면을 흐르는 물 |
| 밤 | 별부엉이의 작은 밤하늘 | 주변 조명 낮추기 / 높이기 | 밝은 주변과 별의 보임 정도 |
| 고속도로 | 고속혜성의 창가 관찰소 | 가까운 나무 / 먼 산 표시 | 이동할 때 가까운 풍경과 먼 풍경의 겉보기 움직임 |

위 캐릭터는 콘텐츠 제작 시 말투 기준이다. 실제 안내자는 **현재 동행 친구**를 유지하고 전문 캐릭터는 필요할 때 이야기 속 삽화로만 등장시킨다. 미보유 종을 등장시켜도 획득·도감 등록으로 처리하지 않는다. 동행 친구가 없으면 길싹이의 안내 배지를 사용하되 보유 캐릭터로 표시하지 않는다.

각 팩은 `관찰 → 예측 → 비교` 세 난이도로 재방문 변형을 만들 수 있다. MVP는 배경별 한 편씩 8편이며, 위 과학 설명은 배포 전 별도 사실 검수를 거친다. 실험은 한 변수만 바꾸고 나머지 조건을 고정해 원인이 섞이지 않게 한다.

## 6. 모바일 화면과 조작

가로 차 안 화면을 유지한다. 중앙·왼쪽은 캐릭터와 작은 실험 무대, 오른쪽은 그림 아이콘이 붙은 큰 버튼 2개, 아래는 짧은 대사 한 줄이다. 전체 화면을 설명 패널로 덮지 않는다.

```text
┌──────────────────────────────────────────────────────────┐
│ 〈 차 안     바다 · 바람 우편배              소리  쉬기   │
│                                                          │
│       창밖 풍경 + 작은 실험 무대       [ 돛 펼치기 ]      │
│       현재 친구        ⛵               [ 돛 접기   ]      │
│                                                          │
│       “같은 바람이 불어. 돛을 어떻게 할까?”               │
└──────────────────────────────────────────────────────────┘
```

- 주요 버튼의 터치 영역은 최소 56 논리 픽셀을 목표로 하고, 가로 소형 화면에서 문구·아이콘 겹침을 확인한다.
- 아이가 버튼을 누르면 즉시 눌림·캐릭터 반응을 보여 주고, 짧은 연출 뒤 다음 선택을 연다. 중복 탭은 한 번만 반영한다.
- 빠르게 움직이는 표적 누르기·기기 흔들기·자동 카메라 회전은 요구하지 않는다. 모션 감소 설정에서는 정적인 전후 그림을 쓴다.
- `[쉬기]`는 항상 접근 가능하다. 중단해도 불이익이 없고, 돌아오면 한 줄 요약과 `[이어 하기]`를 제공한다.
- 읽어 주기는 선택 기능이다. MVP는 자막으로 완주 가능하며 TTS 연동은 후속이다. 안내음을 차량 전체에 자동 송출하지 않는다.
- 화면 속 실험과 실제 창밖 관찰을 구별한다. 실제 옆 창이 보이지 않아도 모든 이야기 완료가 가능하다.

## 7. 배경 변화와 이야기 스케줄

**모든 유효한 배경 변화에 주제를 준비하되, 매번 모달이나 음성으로 끼어들지 않는다.** 아래 시간은 테스트로 조정할 초기 기획값이다.

- 주제 키: `kind + night + highway + rain 여부`. 속도 변화와 rainLevel 1→2만으로 새 이야기를 만들지 않는다.
- 지역은 기존 안정화 결과 사용. 밤·비·고속도로의 주제 변경은 5초 연속 유지 후 확정한다. 터널은 기존 즉시 전환을 따른다.
- 동시 발생 우선순위: 터널 → 새 비 → 새 밤 → 새 지역 → 고속도로. 복합 조건은 이후 검수된 팩에 한해 사용한다.
- 진행 중인 이야기는 현재 가상 실험으로 끝까지 유지한다. 바뀐 현실을 과거 장면으로 표현하지 않고 “방금 본 바다 이야기”처럼 표시한다.
- 대기 주제는 최신 1개만 유지한다. 진행 중 여러 배경을 지나도 알림을 쌓지 않는다. 시작 전 현재 조건을 다시 검사한다.
- 터널을 이미 나왔다면 터널 초대는 철회한다. 이미 시작한 그림자 실험은 계속 가능하다.
- 자동 초대는 이전 초대 이후 최소 90초 간격. `[나중에]` 선택 시 3분간 자동 초대를 쉬며, 아이는 여행 노트에서 직접 시작할 수 있다. 플레이 횟수 제한은 아니다.
- 같은 여행에서 완료한 topicId는 자동 재초대하지 않는다. 같은 환경에 새 팩이 없으면 조용히 두고, 수동 다시 하기는 허용한다.
- 부화·사진·음성 입력 등 주요 흐름과 겹치면 초대를 보류한다. 차 안 화면 밖에서는 배지만 갱신한다.
- 연결이 끊어지면 새 실제 배경 주제는 중단한다. 시작한 이야기는 로컬 콘텐츠로 계속하고 수동 팩은 “상상 탐험”으로 표시한다.

## 8. 주제 생성과 AI의 역할

세 접근 중 **검수된 교육 팩 + 상황별 이야기 조합**을 권장한다.

| 방식 | 장점 | 한계·적용 |
| --- | --- | --- |
| 고정 이야기만 재생 | 오프라인·분기 검증이 쉬움 | 반복감. MVP의 재생 기반 |
| 검수 팩을 상황별 조합 | 환경·친구·이전 발견에 맞춰 다양화 | 템플릿 제작 필요. 권장 운영 구조 |
| 매번 자유 생성 | 높은 표현 다양성 | 사실·분기·지연 검증 부담. 첫 구현 범위에서 제외 |

MVP에서 “생성”은 환경에 맞는 주제 선택과 검수 문장·분기의 조합을 뜻한다. 실시간 AI 생성으로 표시하지 않는다. AI는 제작 단계에서 이야기 변형 초안을 만들 수 있고, 검수된 결과만 콘텐츠 팩으로 배포한다.

후속 실시간 생성에서는 AI가 `topicId/factIds/characterId/difficulty/허용된 actionIds` 안에서 초대·반응 문장만 제안한다. 선택지와 결과·카드 지급은 작성된 그래프가 결정한다. 사실 ID를 달았다는 것만으로 사실 검증이 완료되었다고 보지 않는다.

출력 길이·형식·허용 ID·내용 검사를 통과한 전체 응답만 표시한다. 시간 초과 2초, 네트워크 오류, 검사 실패 시 즉시 검수 문장으로 대체한다. 현재 한국어 생성·검사 적합성은 미검증이므로 기존 영어 Guardian 결과로 대체하지 않는다. 대본·보상·외부 호출을 모델 출력으로 실행하지 않는다.

## 9. 저장·연동 설계 제안

기존 구현에 새 교육 상태가 있다는 뜻이 아니다. 아래 컴포넌트·필드는 신규 제안이다.

```text
차량 환경 → 기존 WindowScene/SceneStabilizer
          → StoryDirector(Dart): 주제 후보·우선순위·진행 상태
          → 검수 StoryPack → Unity: 무대·대사·선택 버튼
          ← 선택 intent   ← 아이의 버튼
          → 검증된 상태 전이 → 로컬 발견 카드 저장
```

- `StoryPack`: id/version, environment 조건, difficulty, factIds, 검수 메타데이터, nodes, allowedActions, endings, cardId. 모든 분기는 종료 또는 명시적 다시 보기로 연결되어야 한다.
- `StorySession`: instanceId, packVersion, nodeId, revision, 선택 이력, paused. `idle → offered → playing → reflecting → completed`와 `paused`를 둔다.
- `StoryIntent`: instanceId/nodeId/actionId/requestId/revision. Unity는 선택 의도만 보내며 Dart가 현재 노드의 허용 행동을 검증한다. 늦은 응답·이전 이야기 입력·중복 요청은 무시한다.
- 기존 `app` 스냅샷에 story 상태를 추가하는 방안을 우선 검토한다. 구현 시 Dart/C# DTO·버전 호환을 함께 갱신하고 계약 문서에 반영한다. 별도 Firebase 교육 상태는 MVP에서 만들지 않는다.
- 카드는 로컬에 `(packId, cardId)` 기준으로 멱등 저장한다. 저장 실패 시 완료 연출과 별개로 “카드를 저장하지 못했어”와 재시도를 표시한다. 저장 성공 전 보관 완료를 주장하지 않는다.
- 보상은 발견 카드와 이야기 결말이다. 기존 재료·친밀도·부화·캐릭터 획득 수치에 연결하지 않는다. 캠프 연동은 후속 계약과 밸런스 검토 대상으로 남긴다.
- 여행 노트는 발견 카드의 신규 보관 화면이다. 종 도감과 같은 정보로 섞지 않고 홈/차 안에서 작은 책 아이콘으로 진입시킨다.
- 아이 이름·나이·위치 원본을 수집하지 않는다. 난이도는 설정 선택값으로 처리한다. 실험 기록은 행동 ID·카드 ID만 로컬에 저장한다.

## 10. 구현 순서와 확인 기준

| 순서 | 산출물 | 통과 조건 |
| --- | --- | --- |
| 1 | 바다 이야기 한 편의 고정 분기·카드 | 두 선택으로 모두 결말 도달, 결과 비교에서 바람·시간 동일 |
| 2 | Unity 차 안 오버레이 + Dart StoryDirector | 버튼이 올바른 연출·다음 노드로 이어짐, 중복 탭·오래된 intent 무시 |
| 3 | 환경 스케줄러 | 장면 노이즈·터널 진출입·동시 태그·연속 변화에서 초대 중복·끼어들기 없음 |
| 4 | 로컬 저장·중단 복귀·오프라인 | 재시작 후 진행 복귀, 저장 실패 재시도, 카드 중복 없음 |
| 5 | 8개 환경 팩과 여행 노트 | 모든 분기·팩 참조 무결성, 과학 사실과 캐릭터 말투 검수 |
| 후속 | 난이도·영어 팩·읽어 주기·제한적 생성 | 언어별 내용 검사와 실패 대체 경로를 별도로 검증 |

필수 시나리오: 바다→터널→산 연속 전환 / 비+밤 동시 진입 / 속도만 변경 / 시작 직후 배경 이탈 / 부화 도중 초대 / 동행 친구 없음 / 오프라인 / 앱 백그라운드 후 복귀 / 카드 저장 실패 / 반복 플레이 / 모션 감소 / 작은 가로 화면.

재미 검증은 먼저 성인 대리 플레이로 조작을 확인하고, 이후 보호자 동반 아이 관찰로 확인한다. 제안 기준은 설명 없이 첫 행동을 선택하는지, 버튼 결과를 알아차리는지, 비교 실험을 자발적으로 해 보는지, 종료 후 발견한 원리 하나를 자기 말로 표현하는지다. 관찰 전 학습 효과나 재미가 검증되었다고 주장하지 않는다. 화면 체류 시간을 최대화하는 것을 성공 기준으로 삼지 않는다.

## 11. 이번 기획 검토 결과

- 실제 `SceneKind` 5개와 수정자 3종에 맞춰 주제를 배치했다. 다리·강은 독립 환경 태그라고 가정하지 않았다.
- 최신 Unity 표시 / Dart 권한 구조를 따르고, 기존 영어 채팅·재료 보상·부화 규칙을 변경하지 않는 확장으로 정리했다.
- 대표 대본의 양쪽 선택 결과·비교·결말을 정의했고, 배경 변경·중단·연결 단절·저장 실패 규칙을 포함했다.
- 앱 코드 변경·실행 테스트·아동 사용성 검증은 수행하지 않았다. 대본의 과학 사실 검수, 실기 가독성, 실제 재미 검증은 구현 단계의 완료 조건이다.
