# Base Camp Implementation Plan

> **For agentic workers:** use subagent-driven-development or executing-plans. User authorizes parallel non-overlapping implementation, routine defaults, and PR review after implementation.

**Goal:** C-owned fixed-role camp with parallel offline jobs, materials, food inventory/book/buffs and learned actions.
**Architecture:** Catalog + pure Dart state engine + serialized Flutter controller/store using existing saved dex and vehicle inputs. Combined with affinity PR93 for the shared controller; reviewed as a follow-up branch. Existing scenes unchanged.
**Tech Stack:** Dart/Flutter and existing SharedPreferences only.
**Spec:** docs/base-camp.md.

## Global Constraints
- Three fixed roles/stations, one concurrent job per role. Worker/learner cannot be double-booked.
- Offline wall-clock progress, exact buff expiry segmentation, no implicit repeating jobs.
- 1000m observed driving or 60s-limited lookOut awards wood/stone/ingredient each1.
- Food1.5x/300s nonstack; facility rates1000/1250/1500; start speed snapshot.
- Stable creature IDs without rewriting dex; saved ownership only; fail-closed read errors.
- Atomic logical snapshot saves, idempotent task completion/cancel and refunds, no data reset on parse failure.
- No new remote/backend/API key/UI/Unity modification; existing defaults unchanged.

## Review Focus
- Material replay across sessions/reconnect and after write failure.
- Large offline jumps crossing food expiry and parallel completion.
- Triple reservation: worker/learner/assignment and cancellation races.
- Repeated IDs and partial storage failure/restart preserving inventory.
- Legacy dex identity and future sourceEggId compatibility.
