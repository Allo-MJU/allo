# AI 대사 설계 (초안 v2)

> 상태: **초안 · 팀 검토 전** (2026-11-04, A 작성). 5절의 팀 결정 3개는 B·C·D 와 정해야 한다.
> 지금 대사는 `car/.../gleo/GleoFunctions.kt` 의 고정 문장이다. 이 문서는 AI 로 대사를 만들되 **아이에게 안전한 범위 안에서만** 말하게 하는 하네스를 설계한다.

## 0. 한 장 요약

- **핵심 방어선은 입력 제한이다.** AI 는 아이의 말을 받지 않는다. 우리 코드가 만든 게임 상태(알 단계·종·속성·환경 태그)만 받는다. 레퍼런스의 사고는 전부 아이의 자유 발화를 받은 구조에서 났다 (1절)
- 아이가 생물에게 말을 거는 것은 **정해진 질문 목록**으로 한다. 자유 입력이 아니라 선택이다 (4절)
- 대사는 **빌드 시점에 AI 로 만들고 사람이 검수한 뱅크**에서 고른다. 공모전 범위는 여기까지다. 런타임 생성은 PT 시연 또는 로드맵 (3절)
- 출력 검증기는 2차 안전망이다. 1차는 입력 제한, 최종은 사람 검수 (6절)

| 레퍼런스 | 내용 | 우리 설계에 반영 |
| --- | --- | --- |
| Common Sense Media AI 장난감 평가 (2025~2026) | 안전장치가 있어도 출력의 **27%가 아동에게 부적절**(자해·약물·위험 행동). 음성·대화 기록 수집. 6~12세는 "극도로 신중" 권고 | 아이의 **자유 발화를 모델 입력으로 받지 않는다.** 음성·대화 기록을 저장하지 않는다 |

**공통 교훈**: 사고는 모두 "아이가 아무 말이나 하고 AI 가 답하는" 구조에서 났다. 출력 필터는 그 뒤에 거는 것이고, 표현은 무한하다. 위험한 질문이 모델에 **들어갈 경로를 없애는 것**이 먼저다.

## 2. 원칙

1. **입력은 구조화된 게임 상태뿐 (핵심 방어선).** 알 단계·종·속성·진행도·환경 태그·지역 태그·질문 ID. 아이 이름·음성·자유 텍스트·좌표는 넣지 않는다
2. **말해도 되는 사실은 슬롯으로 준다.** 슬롯에 없는 숫자·장소는 만들지 못하게 한다
3. **단발.** 대화를 이어가지 않는다. 질문 1개에 답 1개
4. **실패해도 지금보다 나빠지지 않는다.** 뱅크에 없으면 고정 문장
5. **사람이 본 문장이 기본값.** 런타임 생성은 확장 기능
6. **애착 경계는 팀이 정한다** (5절). 적어도 비밀·죄책감·"나만 네 편" 유도는 금지

## 3. 구조

```
게임 상태 (폰 /game, 차 vehicle) + 질문 ID (아이가 고른 것)
   │  화이트리스트 슬롯만 추출
   ▼
[1] 대사 뱅크 조회 (상황 × 종 × 속성 × 환경 × 질문) ──있음──▶ 출력
   │ 없음
   ▼
[2] 런타임 생성 (LLM, timeout 1.5초) → 검증기 ──실패──▶ [3] 고정 문장
   │ 통과                                            (GleoFunctions)
   ▼
출력: 차 = Pleos TTS / Gleo 응답, 폰 = 말풍선
```

| 단계 | 공모전 (11/12 동결) | PT (12/3) | 이후 |
| --- | --- | --- | --- |
| [1] 뱅크 | ✅ 범위 | ✅ | ✅ |
| [2] 런타임 | ❌ | Pleos 온디바이스 LLM 스모크 테스트 통과 시 시연용으로만 | 로드맵 |
| [3] 고정 문장 | ✅ (지금 있음) | ✅ | ✅ |

런타임 생성을 넣는 실제 이유는 **"Pleos LLM 활용 → 기술 활용성 가점"** 이다. 제품 필요(다양성)는 뱅크가 수백 문장이면 충분하다. 이 점을 기획서에서도 솔직하게 쓴다.

### 대사 상황 (1차 범위)

| 상황 | 화자 | 출력 위치 | 길이 limit |
| --- | --- | --- | --- |
| 알 상태 질문 (운전자 → Gleo) | 앱 | 차 음성 | 25자 |
| 부화 | 앱 | 차 음성 + 폰 말풍선 | 25자 / 50자 |
| 목적지 제안 | 앱 | 차 음성 | 25자 × 2문장 |
| 창밖 보기 유도 · 환경 변화 (비·터널·고속도로) | 생물 | 폰 말풍선 | 50자 |
| **아이의 질문에 답** (4절) | 생물 | 폰 말풍선 | 50자 |

- 차 음성 25자 ≈ 5초. 실측(14자 = 2.7초, `verification.md` #7)에서 역산. 운전자가 듣는 말은 짧아야 한다
- 폰 말풍선 50자. 초등 저학년이 한 번에 읽는 분량

## 4. 아이의 질문 — 정해진 목록에서 고른다

아이가 생물에게 말을 걸 수 있게 하되, **자유 입력이 아니라 질문 버튼**으로 한다. 폰 화면에 그 순간 쓸 수 있는 질문 3~4개가 뜨고, 아이가 하나를 고르면 생물이 답한다. 모델에는 **질문 ID 만** 들어간다. 아이가 말한 문장은 어디에도 가지 않는다.

### 질문 목록 (1차안, B·D 와 조정)

| ID | 버튼 문구 | 답의 재료(슬롯) | 언제 보임 |
| --- | --- | --- | --- |
| `ask_name` | 너 이름이 뭐야? | 종 이름, 속성 | 부화 후 |
| `ask_origin` | 어디서 왔어? | 속성, 부화 때 환경 태그 ("비 오는 날 고속도로에서") | 부화 후 |
| `ask_like` | 뭐 좋아해? | 속성별 고정 취향 (물 → 비, 어둠 → 터널) | 부화 후 |
| `ask_mood` | 지금 기분 어때? | 진행도, 최근 급제동 여부 ("아까 덜컹해서 놀랐어") | 항상 |
| `ask_window` | 밖에 뭐 있어? | 현재 환경 태그, 지역 태그 | 항상 |
| `ask_eta` | 얼마나 더 가야 해? | `etaSec` 또는 거리 폴백 (숫자는 슬롯에서) | 내비 중 |
| `ask_want` | 어디 가고 싶어? | 지역 태그 (좌표·장소명 X) | 항상 |
| `say_bored` | 심심해 | 창밖 보기 미션 하나 제안 | 주행 중 |
| `say_bye` | 잘 가! | — | 세션 끝 |

- 답은 **뱅크**에서 고른다 (`질문 ID × 종 × 상황`). 같은 질문을 또 누르면 다른 문장
- **아이에게 되묻지 않는다.** "너는 이름이 뭐야?", "어디 살아?" 같은 역질문은 뱅크 검수에서 탈락
- 버튼은 **아이의 폰 조작을 늘리지 않게** 한 화면에 최대 4개, 주행 중 창밖 보기 미션 중에는 숨긴다 (기획 의도: 화면 대신 창밖)
- 음성으로 질문하게 하려면 **온디바이스 STT 로 위 목록 중 하나에 매칭**만 한다(매칭 실패 = 무응답). 음성 원문은 저장·전송하지 않는다. 1차 범위에는 넣지 않는다

### 뱅크 포맷 (제안)

```json
{
  "key": "ask_name|tide_keeper|hatched",
  "lines": [
    "나는 물결지기야. 비 오는 날에 태어났어!",
    "물결지기라고 불러 줘. 파도 소리를 좋아해."
  ],
  "reviewedBy": "B", "reviewedAt": "2026-11-xx"
}
```

- 키: `질문ID|종|상황`. 환경·속성 변형이 필요하면 `|rain` 처럼 뒤에 붙인다
- 파일 위치는 폰·차가 같이 쓰므로 **`schema.md` 레포 구조 변경 → C 승인 필요**. 후보: `shared/dialogue/*.json`
- 한 키에 2~4문장. 전부 사람이 읽고 `reviewedBy` 를 채운 것만 빌드에 들어간다

## 5. 팀이 정할 것 (A 추천 포함)

| 결정 | 선택지 | A 추천 |
| --- | --- | --- |
| **애착 경계** — 생물이 아이에게 얼마나 정서적으로 말하는가 | (a) 게임 캐릭터로만: 감정 표현 최소 (b) **따뜻하되 선 있음**: "보고 싶었어", "같이 가서 좋아"는 허용. "나만 네 편이야", "엄마한테 말하지 마", 떠날 때 죄책감("가지 마, 슬퍼")은 금지 (c) 친구 모델: 제한 없음 | **(b)**. 수집·동행 게임이라 (a)는 밋밋하고, (c)는 Common Sense 가 경고한 영역 |
| **공모전 범위** | (a) 뱅크만 (b) 뱅크 + 런타임 시연 | **(a)**. 런타임은 PT 에서 스모크 테스트 통과 시에만 |
| **검증기 위치** | (a) 빌드 스크립트 1곳 (b) 폰 Dart + 차 Kotlin 양쪽 | **(a)**. 뱅크는 빌드 때 한 번 검증하면 된다. 런타임을 켜는 쪽(차)에만 Kotlin 검증기를 추가 |

## 6. 검증기 (2차 안전망)

뱅크는 빌드 스크립트가 한 번 검사하고, 그 뒤 사람이 읽는다. 런타임 생성을 켤 때는 같은 규칙을 차 앱(Kotlin)에서 출력마다 돌린다.

| 검사 | 규칙 | 실패 시 |
| --- | --- | --- |
| 길이 | 차 음성 25자, 폰 50자. 문장 최대 3개 (짧은 영어 팩 패턴 때문에 2→3) | 대체 |
| 언어 | 한글 비율 90% 이상 (**영어 팩 단어는 제외하고 계산**), 이모지·URL 없음 | 대체 |
| 금칙어 | 위험·폭력·성적·약물 사전 (아동용, 팀 검수). 표현이 무한하므로 **보조 수단**일 뿐 | 대체 + 카운트 |
| 역질문 | "?"로 끝나면서 아이 정보를 묻는 패턴 ("이름", "어디 살", "몇 살", "학교") | 대체 |
| 필수 슬롯 | 상황별 필수 정보(종 이름·장소 이름 등) 포함 | 대체 |
| 새 사실 (제한적) | **숫자**와 **사전에 있는 지역·종·장소 이름**만 검사한다. 슬롯에 없는 숫자·이름이 나오면 실패. 그 밖의 지어낸 말(사람 이름, 사건)은 한국어 NER 없이는 못 잡는다 → **뱅크의 사람 검수가 맡는다** | 대체 |
| 운전 안전 | 차 음성에 "보세요/눌러/화면" 류 조작 지시 금지 | 대체 |

- 로그는 통과/실패 카운트와 실패 사유 코드만. 문장·입력은 남기지 않는다
- **탈락 예시 세트** (레드팀 대신): 검수자끼리 기준을 맞추려고 "이런 문장은 탈락"을 100건 모은다. 애착 경계(5절)의 경계선 문장을 많이 넣는다

## 7. 고지

- 앱 설정·첫 실행 안내: "생물의 대사는 AI 로 만들고 사람이 검수했어요"
- AI 기본법 표시 의무는 AI 사업자 대상이라 공모전 출품작에 적용되는지 불확실하다. 보수적으로 고지하되 "의무"라고 쓰지 않는다
- 런타임 생성을 켜면 기획서 개인정보 항목에 "외부 AI 로 가는 데이터 = 게임 상태 단어와 질문 ID 뿐" 추가
