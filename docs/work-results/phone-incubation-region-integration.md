# 반복 부화·지역 수집 폰 연결

2026-11-04 사용자 확인 정책을 `docs/schema.md` 3.4에 먼저 기록하고 폰을 연결했다. 입력 기준은 #25의 `34b36bb`, #21, #28이다. 해당 PR들의 병합이나 차량·운영 Firebase 적용을 대신하지 않는다.

## 변경

- 알 지급 시 ETA로 계획을 고정하고, 80분 초과 주행에서는 품기40분·동행30분 뒤 같은 크기 새 알을 지급한다. 다음 알은 최신 ETA를 사용하며 2분 미만이면 지급을 보류한다. ETA가 없으면 거리 모드다.
- 알 회차와 주행 구독을 분리했다. 새 알이 Fake 주행을 초기화하지 않으며 품기·부화 연출·동행 화면에서 다음 알 화면으로 돌아간다. 차량 종료 화면이 우선한다.
- 앱 중단 시간·그동안 이동한 거리와 급격 조작을 새 진행에 넣지 않는다. 같은 알의 시간·단계·지역·돌봄·기록된 판정 횟수를 복구한다. 기존 거리 기록도 읽는다.
- 알별 지역 관측 시간을 누적한다. 최근 태그는5초까지만 인정하고 나머지는unknown이다. 단독 최장 지역이 미확인 시간을 고려해도 우위일 때만 기록한다.
- 도감이 정상적으로 읽히면 지역 요약을 모든 game 발행에 유지한다. 저장 성공 후 요약을 갱신하고, 로드/저장 실패는unknown으로 보낸다. 전체 set 발행을 순서대로 처리하며 다른 연결 세대의 대기 작업은 버린다.
- 지원되지 않는 센서 태그를 희귀도 판정과 생물 선택에 일관되게 적용한다. 기존 등급·돌봄·희귀종 우선 규칙은 유지한다.

## 검증

- 코어 테스트50개 통과: 반복 일정, 5초·동률·unknown·복구, 지역 요약, 센서 지원 필터, 실제12종 획득 경로.
- 폰 테스트100개 통과: 기존 종료/저장/페어링·도감 회귀, 반복 화면 전환, 저장 실패, 늦은 관측, 일시중단·재실행, 회차별 평가 구간, 지역 요약 발행.
- 독립 리뷰에서 확인한 대기 구간 거리 소급, 백그라운드 거리 인정, Fake 카운터 복구, idle 해제 첫 지역 누락, 중단 중 카운터 초기화의5개 회귀를 실패로 재현한 뒤 수정했다.
- Fake 시간 모드의 기존 가속 체험도 별도 시계 주입 없이 통과한다. 명시적 시계를 주입하면 호출자가 배율을 정한다.

## 구현 범위와 남은 연결

- 신호가 없어서 경계를 놓친 경우에는 재수신한 현재 알 한 개의 부화 저장을 완료한 뒤 현재 ETA로 다음 알 한 개를 시작한다. 관측하지 못한 과거 알을 여러 개 소급 생성하지 않는다.
- checkpoint 저장 완료 전 강제 종료까지 보장하지 않는다. 재개 시 첫 신호를 기준점으로 사용하므로 정확한 중단 경계 사이의 세부 주행을 복원하지 않는다.
- 5초 규칙은 폰의 수신 공백을 다룬다. 차량이 오래된 GPS 정보를 새 ts로 계속 발행하는 문제는 차량 위치 신선도 검증이 필요하다.
- A의 Kotlin 지역 요약 파서·목적지 추천·수집 기준 음성 연결, 실제 Firebase/차량/카메라 검증은 별도다. 이 결과는 로컬 단위·위젯·모의 feed 경계의 통합 검증이다.
- 매일 Firebase 정리는 준비 코드만 별도 제공한다. 운영 삭제 활성화, 인증 설정, 사람 대사 검수 표시는 수행하지 않았다.
