# T6 — 차량 시나리오 로컬 검증

## 변경과 실행

- `vc.sh`의 heartbeat, PUT, 종료 요청은 HTTP 오류와 연결 오류를 실패로 반환하며 연결 5초·전체 10초 제한을 둔다. heartbeat 실패 시 PUT을 보내지 않는다. 자동 선택은 Pleos 에뮬레이터가 정확히 하나일 때만 하며, 여러 개면 `ANDROID_SERIAL`을 지정한다.
- 두 시나리오는 양의 정수 인자를 검증하고, Park·제어 입력 0·와이퍼/전조등 off·뒷좌석 비점유 후 우측 탑승으로 시작한다. 요청 또는 `adb`, `sleep` 실패 시 비정상 종료한다. 성공 메시지는 신호 전송만 뜻한다.
- `python3 scripts/tests/test_vehicle_scenarios.py`: `curl`, `adb`, `sleep` 전부 임시 로컬 stub으로 대체한다. HTTP 및 전송 실패, 명령 실패, 기기 선택, 인자, 초기화, 순서, 정상 경로를 검증한다. 실제 네트워크나 기기에 연결하지 않는다.
- 실패·중단 시 자동 복구나 종료 heartbeat는 보장하지 않는다. 실제 시연자는 VC 상태와 연결을 확인하고 수동으로 정리해야 한다. 신호 초기화는 게임 세션·누적 거리·급제동·폰 저장 상태를 지우지 않는다.

## 시나리오와 부화 증거 구분

기본 rainy는 90km/h 유지 120초로 이 구간의 명목 거리가 약 3km다. 가감속을 포함해도 small 거리 부화 기준 5km에 미달하며, 이 수치는 실제 앱에서 측정한 거리가 아니다. 인자 `scripts/scenario_rainy_highway.sh 200`은 90km/h 유지 구간의 산술상 5km이지만, 경계 여유와 앱의 샘플링·거리 기준점이 있으므로 완주를 보장하지 않는다. `docs/verification.md` #4에 따르면 에뮬레이터 주행만으로 odometer가 자동 증가하지 않아, 속도 유지 시간만 늘려도 거리 부화가 보장되지 않는다. `DEMO_SCALE`은 `docs/demo-scenario.md`에 TODO로만 기록되어 있다.

T0 통합 후 격리된 테스트 세션에서 다음을 별도로 확인해야 한다.

1. 폰에서 새 small 알, ETA null(거리 모드), 누적 거리 기준점 및 capabilities를 확인한다. 기존 세션 또는 이전 알 상태를 재사용하지 않는다.
2. 차량 앱이 실제로 사용하는 거리 원천을 확인한다. Odometer 사용 시 `docs/verification.md` #4의 첫 샘플 기준점과 km→m 변환을 고려해, 승인된 테스트 환경에서 기준점 이후 **5km 이상**의 단조 증가를 충분한 여유와 함께 단계적으로 공급한다. 직접 주입 여부·간격은 A/C 통합에서 결정한다. 실제 거리 readback이 기준을 넘는지 확인한다.
3. `/vehicle`의 타임스탬프·거리·태그와 폰의 진행 상태를 관찰하고, 폰의 `stage=hatched` 및 종·속성·등급, 필요하면 도감 저장까지 확인한다. 전송 2xx만으로 앱 수신이나 부화를 증명할 수 없다. 터널은 주간 전조등 조건도 확인한다.

근거: `docs/verification.md` #1·#2·#4의 VC 와이퍼/전조등/odometer 실측, `phone/packages/allo_core/test/hatch_timer_test.dart`의 small 5km 경계. 부화 및 종 결과는 실제 앱 로직과 세션 조건에 달려 있다. SDK의 추가 동작은 가정하지 않았다.

## 통합 담당자에게 제안 (공유 파일 미수정)

- `docs/demo-scenario.md` 20행의 `DEMO_SCALE=100`을 구현된 옵션처럼 사용하지 말고 TODO로 유지하거나, 실제 채택 시 B/C가 구현·테스트·표시 방법을 합의한다. 기본 시나리오 실행 완료와 부화 readback을 별도 체크 항목으로 기록한다.
- `scripts/fake_vehicle_feed.sh`는 별도 소유 범위다. 기존 SID의 `vehicle.distanceM`에서 0으로 되돌아가는 재시작을 피하도록, 신규 세션 전용인지 또는 시작 거리 인자/초기 상태 readback을 받을지 정하고 누적 단조성 테스트를 추가한다. HTTP 실패 처리도 동일하게 제안한다.
- 종료·정리 정책과 세션 재사용/이벤트 정리는 운영 데이터에 영향을 주므로 T0 통합 시 별도 합의한다. 이번 작업은 운영 Firebase·연결 에뮬레이터에 쓰지 않았고 live readback·앱 전체 완주는 미검증이다.
