# 친구별 부탁과 방문 이력 검증

2026-11-15. 공유 작업 폴더 `fix/live-service-integration-20261115`의 `78bf749` 위 로컬 변경이다. 기존 수집/간식/마을 선택과 동시 작업의 차량 코너링·연결 모드 변경을 보존했다. 커밋·푸시·운영 배포·APK/Unity export 교체는 수행하지 않았다.

## 구현한 사용자 흐름

- 소유 개체마다 최초 관측 anchor를 저장하고48시간 주기를 계산한다. 동일 종의 다른 소유 개체도 독립이다. 미열람 초대 ID도 다음 구간으로 갱신한다. 미수락 이전 구간은 수락할 수 없고, 수락한 부탁은 완료까지 유지한다.
- 마을의 표시4마리 옆에?를 표시한다. 상세를 열어도 부탁 본문/TTS는 자동으로 열리지 않는다. 상세의?를 눌러야 서버 본문을 읽는다. 표시되지 않은 소유 친구도 도감에서 부탁을 확인할 수 있다.
- 먹이/기존 고정 스토리와 연결한 관찰/여행 부탁을 지원한다. 음식은 기존 재고1개 차감·효과·부탁 완료가 같은 저장에 들어간다. 관찰은 명시적인 사용자 확인이며 풍경을 센서가 검증했다는 주장이 아니다. 새로운 완료 재화를 추가하지 않았다.
- 스토리 자료 없는 legacy 친구에게 없는 과거를 만들지 않는다. 해당 이야기 요청은 먹이 부탁으로 반환하며 확인된 여행 이력을 활용할 수 있다.
- 여행 부탁은 실제 확인된 방문을 제외한 기존18개 후보에서 장소를 고르고 보호자에게 제안한다. 차량의 기존 주차·연결·활성 경로 보호와 운전자 수락을 유지한다. 경로 요청 성공은 완료가 아니다.
- 실제 도착·정확한 장소·수락 이후 시각·동행 개체가 맞아야 여행 부탁을 완료한다. 친구의 실제 바다 방문이14일 이상 전인 경우에만 해당 장소를 언급하는 문구를 쓴다. 이력 미확인은 빈 이력이나 첫 방문으로 취급하지 않는다.
- Firebase 영속 `travelHistory/{phoneUid}`에 방문·장소 요약·동행 친구별 장소의 최신 도착을 같은 transaction으로 기록한다. 소유 폰만 읽고 클라이언트 직접 쓰기는 금지한다. GPS 좌표·주소·이동 경로는 보내지 않는다.
- 최근200개 방문 밖으로 밀린 기록도 새 친구별 장소 인덱스가 있으면 완료와14일 문구에 활용한다. 기존 인덱스 도입 전 자료의 백필은 하지 않았다.

## TDD와 독립 검토에서 확인한 회귀

- 기본 마을/상세/도감/부탁 UI9개를 구현 전 실패 확인했다. 헤더 닫기·Dex 확인창 Back·한글 지역명3개와 완료/Back/화면전환 시 host laterQuest 전송8개도 실제 실패 후 수정했다.
- Unity 실제 직렬화에서 누락 placeId가 빈 문자열임을 캡처하고 폰 validator와 수락 파라미터를 정규화했다. 동일 payload의 bridge 회귀를 확인했다.
- 서버가 저장하는 map-key visitId·문자열 routeRevision·destination-arrived evidence에 맞춰 폰 파서를 고쳤다. 읽기 실패/미확인 후보 노출,14일 경계, 친구별 지연 응답, 중복 수락, 늦은 완료 감사 반응을 검증했다.
- 완료 카드를 접을 때 UI만 닫고 host opened 상태가 남아 다음 초대가 차단되던 경로를 수정했다. 명시적 닫기는 현재 개체/부탁 ID를 보내고, 권위 snapshot 교체 정리는 새 요청을 보내지 않는다.
- 선택 소유 ID는 fishing profile과 한 번에 저장한다. 앱 재시작·동일 종·완전히 같은 legacy 행2개에서도 정확한 소유 ID를 복원한다. 이전 데이터에서 서로 구분할 수 없으면 추측하지 않는다.
- SharedPreferences commit 실패가 메모리에는 적용될 수 있는 outbox 재시도 회귀를 검증했다. 동일 값이 메모리에 있어도 디스크 쓰기를 다시 시도한다.
- 추가된 퀘스트 이력 준비가 마을의 기본 시작을 막지 않도록 선택적 초기화를 분리했다. 최종 전체 Flutter에서 기존 demo widget startup도 통과했다.

## 실제 화면과 검증 한계

[실제 Unity PlayMode 캡처](../work-results/unity-phone/quests-2026-11-15/README.md)를1600×720/1024×576에서 확인했다. synthetic AppState를 입력한 UGUI 실행 캡처이며 설치 APK/실제 DB/실차 시연 증거가 아니다. 임시 촬영 스크립트는 제거했다.

실차 NaviHelper의 콜백 전달·순서는 확인하지 않았다. 현재 운전자 수락 목적지는 이름과 차량 내부의 근사 좌표 대응을 이용하므로500m 이내의 매우 가까운 동명 장소를 완벽히 구별하지 못한다. 경로 종료 뒤30초를 넘긴 도착, 앱 재시작/페어링 전에 시작된 경로는 상관관계가 없어 기록이 누락될 수 있다. 세션 ACL 삭제 뒤 outbox는 소유자를 확인할 수 없어 대기한다. 요청/주차/종료를 임의의 실제 방문으로 바꾸는 fallback은 두지 않았다.

서버·Firebase Functions/rules를 운영 환경에 배포하고 새 APK를 만들기 전에는 설치된 앱에 이 기능이 반영된 것으로 보지 않는다. 기존 스토리 원본의 사람 검수 상태도 바꾸지 않았다.
