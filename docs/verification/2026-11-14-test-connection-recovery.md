# 테스트 연결 깜빡임·알 복구 수정

2026-11-14 사용자 신고를 실행 중인 Android 에뮬레이터와 저장 기록에서 확인했다. 데이터 삭제 없이 수정 APK로 업데이트하고 다시 검증했다.

## 원인

- 신고 당시 실제 Dart 런타임 필드는 `paired=true`, 사용자 요청 대기 0, `game.busy=false`, 알 상태 `failed`였다. 연결 자체는 가상 주행에 성공한 상태였다.
- 주행 샘플과 거점 작업의 자동 저장도 `camp.busy`를 켰다. Unity가 이를 화면 전체의 처리 상태로 받아 안내를 깜빡이고 입력을 잠시 비활성화했다.
- 이전 데모 세션에는 이미 실패한 알의 지급 기록이 남아 있었다. 기존 일반 연결을 재사용한 테스트 버튼은 같은 여행을 복원하므로 새 알을 지급하지 않았다.
- 도착 시간 없는 주행 신호도 계속 ‘차량 신호를 기다려요’로 표시해 연결 상태를 오해하기 쉬웠다.

## 수정

- 거점의 백그라운드 저장을 전체 UI busy에서 제외한다. 사용자 명령은 기존 UnityAppController 요청 큐가 처리 상태를 유지한다.
- 데모 전용 `testPair`는 진행 중인 알을 유지한다. 이전 알이 종료됐으면 기존 여행 종료 저장을 먼저 마친 뒤 새 데모 여행을 시작한다. 실차 모드와 연결 창 밖에서는 거절한다.
- 초기 알 저장 실패를 성공으로 넘기지 않는다. 연결 창을 유지하고, 부분적으로 연결된 상태라도 빠진 알 지급을 재시도한다. 저장 실패·이탈 중에는 새 알을 중복 지급하지 않는다.
- 완료 배지는 `테스트 연결됨`으로 표시한다. 신호는 있으나 ETA가 없는 경우에는 `도착 시간 정보가 없어요`로 구분한다.

## 검증

- 새 Flutter 회귀 9건: 배경 주행/거점 저장 busy 분리, 사용자 요청 busy 유지, 최초·반복 테스트 연결, 저장된 실패 알 복구, 실차·다른 화면 거절, 저장 실패/재시도, ETA 없는 신호 표시. 수정 전 실패를 확인한 뒤 통과했다.
- Flutter 전체 **510/510 통과**, 변경 Dart 파일 분석 정상.
- Unity 연결 UI **6/6 통과**. 공유 작업본 전체는 263/263 통과했으며, 여기에는 별도 진행 중인 마을 동작 테스트가 포함된다. 이번 커밋에는 연결 배지 변경만 포함하고 마을 작업은 제외했다.
- 독립 코드 검토에서 초기 알 저장 실패의 성공 오판을 추가로 재현·수정했다.
- Android export와 APK 빌드 성공. 마지막 Dart 수정 후 APK 재빌드 6.3초, API36 에뮬레이터에 데이터 유지 설치·시작.
- 실제 연결 창에서 테스트 연결을 누른 뒤 런타임 `paired=true`, `stage=incubating`, `egg.active=true`, 사용자 요청 대기 0을 확인했다. 기존 저장 자원과 보유 친구는 유지했다.
