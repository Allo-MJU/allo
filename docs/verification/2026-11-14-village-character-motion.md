# 거점 걷기와 오른쪽 캐릭터 상세

2026-11-14. 캐릭터 그림을 작게 흔들던 효과를 목적지까지 걷고 쉬는 동작으로 바꾸고, 상세를 오른쪽 패널 안으로 정리했다.

## 구현

- 기존 6종의 `phone/assets/poses/<species>/run-sheet.png`를 그대로 재사용한다. 4×2의 8프레임을 160ms 간격으로 재생하며 진행 방향에 맞춰 그림만 뒤집는다. 새로운 GIF 디코더나 런타임 패키지는 추가하지 않았다.
- 보유 개체별로 목적지·휴식 시간을 유지한다. 기존 잔디 영역과 오른쪽 메뉴를 고려한 범위 안에서 초당42 UI 단위로 걷는다. 이름표는 함께 이동하고 글자 방향은 유지한다.
- 누르는 중, 지도 관성, 상세/시설/확인창, busy와 움직임 줄이기 설정에서는 배회를 멈춘다. 프레임·방향·위치 변화는 표현일 뿐 보상이나 저장 상태를 바꾸지 않는다.
- 오른쪽 상세는 이름·역할, 움직이는 미리보기, 실제 작업/담당 상태, 기존 설명, 배운 행동과 요리를 보여 준다. 개체 ID와 사용 전 확인 흐름은 유지한다. 긴 내용에는 스크롤 표시를 둔다.
- 화면 갱신 시 지도 위치와 상세 애니메이션 위상을 보존한다. 그림 로딩 도중 화면이 숨겨졌다면 다시 활성화될 때 미완료 로딩을 재개한다.

원본·생성 출처는 `phone/assets/poses/README.md`와 각 종의 provenance에 있다. 원본 PNG를 수정하거나 다른 종의 그림으로 대체하지 않았다. Flutter에는 사용한 걷기 시트 6개만 추가 등록했다.

## 검증

- 기능 구현 전 관련25건 중14건이 새 동작/렌더러 부재로 실패하는 것을 확인했다.
- 최종 Unity EditMode 전체264/264, PlayMode 입력 테스트3/3 통과. 전체에는 같은 작업본에서 병행 중인 차량 연결 회귀2건이 포함되어 있다. 이번 시설 변경 소유 범위는262건이며 병행 변경은 별도로 보존한다.
- 독립 코드 검토에서 로딩 중 화면 전환 문제를 찾아 수정했다. 비활성화·재활성화 회귀를 추가했다. Android 네트워크 요청의 중간 중단 자체는 Editor의 동기 로더 테스트로 검증하지 않았다.
- 실제 Unity PlayMode UI를 1600×720과1024×576에서 렌더링했다. 6초 동안4캐릭터가 각각 약90~180 UI 단위 이동하고8프레임을 보였다. 상세는8프레임이며 스냅샷 전후 프레임6이 유지됐다.
- 스냅샷 전후 지도 위치, 상세 중 지도 위치, 움직임 줄이기 위치 변화는 모두0이다. overflow에 맞는 스크롤 표시도 확인했다. 독립 화면 검토 판정은 이 범위에서 ship이다.

화면·GIF·측정 결과: `docs/work-results/unity-phone/village-motion/`. GIF는 실제 Unity UI의 짧은 캡처를 인코딩한 검증용 미리보기이며, 앱은 PNG 시트를 직접 재생한다. 전체 프레임 PNG는 `/tmp/allo-village-motion-frames/`에만 두었다.

## Android 확인

Unity Android export와 debug APK 빌드(90.8초)에 성공했다. APK 내부의 여섯 걷기 시트 경로를 확인하고, API36 에뮬레이터에 기존 데이터를 유지하며 업데이트했다. 실제 앱의 마을 화면을2초 간격으로 캡처하여 위치와 다리·날개 자세의 변화를 육안 확인했다. `android-walk-1.png`, `android-walk-2.png`가 해당 실행 증거다.

APK SHA-256: `fc71b8f24dd6996b53823df40010faa6d689d709b4d6f693a7fdec76fd94e311`. Android 실행 작업본에는 병행 중인 차량 연결 수정도 들어 있다. 이번 시설 커밋에서는 해당 수정의 파일·공유 파일 내 다른 변경을 포함하지 않고 보존했다. Android에서 상세 열기/닫기·로딩 중 이탈을 반복 터치한 검증이나 실제 차량 테스트는 하지 않았다.
