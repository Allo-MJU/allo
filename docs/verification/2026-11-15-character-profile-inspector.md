# 캐릭터 소개와 오른쪽 상세 정리

## 결과

왼쪽의 기존 기쁨 애니메이션은 유지하고, 오른쪽은 이름·역할, 한 줄 성격 소개·태그, 현재 상태, 행동과 요리 순서로 정리했다. 별도 배경 카드들을 반복하지 않고 여백과 얇은 구분선으로 묶었다.

이야기12종과 기존6종의 원문 persona에서 표시용 소개와 태그를 만들었다. 새로운 출신·능력·사건은 추가하지 않았고, 독립 검토에서18종 모두 원문과 대조했다. 문구의 출처와 갱신 범위는 `docs/character-profile-provenance.md`에 기록했다.

## 데이터와 동작

- `phone/assets/data/character_profiles.json`은 `id`, `summary`, `traits`만 가진 표시용 메타데이터다. 서버 persona·지식·시스템 지시·스토리 본문을 앱으로 옮기지 않았다.
- Flutter는 정확한 speciesId로 소개를 연결하고 Unity snapshot에 optional personaSummary/personaTraits를 보낸다. 같은 종의 보유 개체는 같은 소개를 사용하며, 미등록 종은 빈 값으로 처리한다. 구형 snapshot도 표시할 수 있다.
- 현재 작업·담당 역할·남은 시간·요리 효과는 실제 상태 데이터만 표시한다. 행동과 음식 사용은 선택한 보유 개체 ID를 유지한다.
- 배운 행동이 없으면 훈련장 안내, 준비된 요리가 없으면 주방 안내를 제공한다. 기존 시설 상세로 이동할 뿐 새 비용·보상 규칙을 만들지 않는다.

## 검증

- Flutter 표시 연결 신규3건: 데이터 누락 실패를 확인한 뒤 통과. 전체 Flutter513/513 통과, 관련 파일 분석 정상.
- Unity 화면 신규/수정4건: 소개·태그/비어 있는 상호작용/정확한 요리 대상 전달이 구현 전 실패한 것을 확인했다.
- 캡처에서 배지 높이가16px로 줄어 텍스트가 사라지는 문제를 발견했다. 할당 높이가 텍스트 preferredHeight보다 작은 회귀를 확인한 뒤 배지 높이를32px로 수정했다.
- 최종 Unity EditMode276/276, PlayMode3/3 통과.
- 실제 Unity PlayMode 두 해상도에서 역할·태그의 글자 생성과 높이를 검증했고, 길싹이·웅덩이삐약 소개, 빈 행동/요리 상태의 상단·하단을 육안 확인했다. 수정 후 독립 코드·화면 검토에서 추가 P1/P2 없음.
- 기존 걷기 PNG/GIF4개는 바이트 단위로 유지했고, 상세 GIF는 기존 기쁨 동작의1.22초 재생 간격을 유지한다.

화면과 GIF: `docs/work-results/unity-phone/village-motion/`. 캡처는 검증용 상태 fixture를 쓴 실제 Unity UI이며 실제 저장 데이터나 실기기 캡처로 해석하지 않는다.
