# 실행 중 테스트 연결과 가상 자이로

2026-11-15 · `fix/live-service-integration-20261115`

## 사용자 요청과 구현 범위

기존 실제 연결·게임·AI 기능을 유지하면서 차량 연결 화면의 “테스트 연결”에서 가짜 주행 데이터를 사용한다. Android Studio에서 자이로를 조작하는 방법도 안내한다. APK 제작·설치는 계속 보류한다.

## 동작

- 실제 연결용 Unity 앱에도 미연결 상태의 테스트 연결 버튼을 제공한다. 이미 실제 차량에 연결됐으면 기존 연결 해제 후 테스트에 진입한다.
- 실제 controller/feed는 보존하고 테스트용 controller 묶음만 별도로 만든다. 도감·거점·낚시·연결 정보는 `test-connection` 로컬 프로필로 분리한다. 테스트 feed의 차량 상태·게임 발행은 Firebase에 쓰지 않는다.
- 기존 `sceneTour`를 재사용한다. 15초마다 일반 도로→해안→산→도시→터널→밤 도시→비 오는 고속도로를 순환한다. 표시용 조향은 중립→오른쪽→중립→왼쪽을 6초 간격으로 반복한다. 조향 수신 시각에는 가속 게임 시각이 아닌 실제 wall clock을 사용한다.
- 자이로·움직임 줄이기 설정과 AI API 설정은 기존 방식을 유지한다. 가짜 데이터는 차량 신호에 해당하며 AI 응답·사진 API를 가짜 성공으로 바꾸지 않는다.
- 테스트 화면에서 “실제 차량 연결로 돌아가기”를 제공한다. 테스트 상태에서는 실제 QR·수동 연결을 가짜 feed로 처리하지 않도록 막는다.
- 비활성 실제 controller의 퀘스트 폴링을 멈추고, 이전에 시작한 조회·템플릿 응답이 늦게 와도 상태를 바꾸지 못하게 한다. 이미 시작된 네트워크 요청 자체의 취소를 보장하는 것은 아니다.
- 같은 테스트 주행에 재진입하면 알·거리·시각을 이어간다. 실제 모드에 있는 동안 가짜 시간·거리·캠프 보상은 멈춘다. 앱을 재실행한 경우에도 같은 세션의 저장 관측값을 복원하고 알 진행도에서는 이전 거리를 다시 더하지 않는다. 명시적으로 끝낸 새 테스트 세션은 0m부터 시작한다.
- 체크포인트·낚시 저장 재시도가 남으면 모드를 바꾸지 않는다. 같은 프레임에 대기한 실제 페어링 요청도 숨은 controller에서 실행되지 않는다.
- 하나의 Unity 엔진에 controller만 넘길 때 ready·native 활성 상태를 재전달하고 revision을 단조 증가시킨다. 이전 controller가 새 화면을 덮지 못하게 sender를 분리한다. API 리소스는 원래 소유자가 한 번만 닫는다.

## Android Studio 자이로 사용

1. 새 소스가 반영된 테스트 앱에서 테스트 연결로 차 안에 들어간다.
2. 에뮬레이터의 `⋮` → `Virtual sensors` → `Device Pose`를 연다.
3. `Rotate`에서 기본 자세를 정한 뒤 앱 설정의 “정면 다시 맞추기”를 누른다.
4. `Yaw`를 좌우로 움직이면 좌우 시선, `Pitch`를 움직이면 상하 시선을 확인할 수 있다. 앱의 상하 시선은 ±35도로 제한되고 수평선은 유지한다.
5. 메뉴가 안 보이면 에뮬레이터를 Android Studio 내부 패널 대신 별도 창으로 실행한다.

공식 문서: https://developer.android.com/studio/run/emulator-extended-controls

이번 검증은 소스 테스트와 Editor 실행이다. APK 빌드·실제 에뮬레이터 앱 갱신·물리 기기 센서 검증·원격 배포는 수행하지 않았다. 다른 채팅의 수집·퀘스트 등 동시 변경은 보존했다.
