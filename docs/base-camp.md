# 거점과 캐릭터 역할 구현 기준

2026-11-12 사용자 선택: 종별 역할 고정, 지정된 시설 자리의 건설·확장, 거리/활동 재료, 음식의 작업 보너스와 요리 도감, 훈련 행동 습득. 건설·요리·훈련을 각각1개씩 동시에 진행하며, 앱을 닫아도 실제 시간이 흐르면 진행한다. 작업에는 개체를 배치하고 같은 개체를 중복 작업에 쓰지 않는다. 시설 확장은 콘텐츠와 성능을 함께 개선한다.

이번은 C의 순수 규칙·로컬 저장·폰 입력 API를 구현한다. 최신 dev에서 독립적으로 개발하며 부화 PR #93의 병합이나 화면·에뮬레이터를 기다리지 않는다. 기존 도감 ID/획득 조건은 바꾸지 않는다. 화면/3D 애니메이션과 실제 기기 검증은 별도다.

## 역할과 개체

현재 게임의12종을 기준으로 아래 고정 역할을 부여한다. 디자인 목록과 다른6종의 이름/ID는 이 기능에서 임의 교체하지 않는다.

- builder: road_sprout, bridge_hopper, mountain_sprite, highway_comet
- cook: puddle_pip, river_glider, tide_keeper, sea_mist
- trainer: lamp_moth, tunnel_moth, star_owl, storm_lantern

같은 종도 획득 건마다 개체를 구분한다. 원본 도감에 sourceEggId가 있으면 이를 활용하고, 기존 데이터는 원본의 정규화된 항목+중복 순번을 키로 거점 로컬 ID를 한 번 배정해 저장한다. 기존 도감 행을 다시 쓰지 않는다. 알 품기 중인 종은 소유로 인정하지 않으며 정상적으로 읽은 저장 도감만 사용한다. 읽기 오류를 빈 도감으로 바꾸지 않는다.

각 역할 칸에 소유 개체를 배치한다. 잘못된 역할/없는 개체/다른 작업에 쓰는 개체는 거절한다. 훈련은 trainer와 다른 개체인 학습 대상도 예약한다. 단순 배치와 작업은 구분하며 배치된 비작업 개체는 다른 행동에 사용할 수 있다.

## 시설과 콘텐츠

처음에는 모두0단계다. 건설소가 없어도 builder가 건설소를 지을 수 있다. 주방/훈련소 건설은 건설소1단계부터 가능하다. 시설 확장은 정확히다음1단계이며 최대3이다. 건설 작업 칸을 사용하므로 기존 요리·훈련과 병렬 가능하다. 진행 중 작업의 시설 속도는 시작값으로 고정하고, 확장 보너스는 이후 작업부터 적용한다.

요리 완료 시 음식 재고와 누적 제작 횟수를 함께 저장한다. 먹어도 도감 기록은 남는다. 행동은 개체별로 습득하며 이미 아는 행동을 다시 훈련하지 않는다. C는 소유·습득 조건을 검사해 사용할 수 있는 행동을 반환하고, 동행/거점 화면은 그 결과에 맞춰 연출을 재생한다. 행동 재생만으로 별도 재료를 지급하지 않는다.

## 시간·보너스·재료

시간은 호출자가 제공하는 epoch 밀리초다. 앱 복귀/재시작 때 저장된 시점부터 현재까지 작업을 계산하여 결과를 한 번 반영한다. background 프로세스나 푸시를 전제하지 않는다. 작업은 자동으로 다시 시작하지 않는다. 기기 시계 후퇴는 진행을 되돌리거나 보상을 반복하지 않으며, 제품 수준 서버시계/부정사용 방지를 구현했다고 주장하지 않는다.

음식은 현재 진행 중인 작업에도 먹인 이후 남은 구간부터 적용한다. 만료 전후 구간을 나눠 계산하며 완료된 작업량에 소급 적용하지 않는다. 모든 작업과 음식 만료를 같은 시각으로 먼저 정산한 뒤 새 입력을 처리한다. 저장/재시작과 tick 크기에 따라 완료 시점·재료·재고가 달라지면 안 된다.

주행은 세션 ID, 원본 snapshot 시각, 세션 누적거리로 중복/역순/거리 후퇴를 걸러낸다. 최초 관측 및 재연결/앱 복귀 직후는 기준점만 잡고 관측하지 않은 구간의 거리를 보상하지 않는다. 1km 미만 잔여 관측 거리는 세션 사이에 보존한다. 작업의 오프라인 진행과 주행 재료의 관측 기준은 별개다. 지역별 재료·좌표 전송·소급 주행 추정은 넣지 않는다.

거리는 밀리미터 고정 단위로 누적해 짧은 간격의 소수점 거리도 보존한다. 저장 큐에 있던 복귀 전 샘플은 호출 당시 세대로 정산하고 새 복귀 기준점을 소비하지 않는다. 현재 VehicleFeed는 통신 재연결을 별도 이벤트로 제공하지 않으므로, 구독 재시작/복귀를 아는 호출부가 `beginDrivingSession`을 호출해야 한다. 조용한 통신 단절을 자동 탐지한다고 가정하지 않는다.

## 저장·오류·연결

모든 변경은 복제한 상태에서 계산하고 단일 저장 큐를 통해 성공한 뒤 UI에 공개한다. 재료 차감·작업 생성, 완료 효과·처리 ID, 음식 소비·보너스는 각각 같은 상태값으로 저장한다. 저장 실패 시 이전 공개 상태를 유지하고 재시도를 제공한다. 손상/미지원 버전 데이터는 보존하며 빈 프로필로 덮지 않는다. 같은 taskId를 재시도해서 재료나 결과를 두 번 적용하지 않는다.

개체 목록을 정상적으로 갱신한 뒤 작업자의 소유가 사라지면 해당 작업을 취소·전액 환급한다. 이미 만든 시설·요리 도감은 보존한다. 소유 읽기 실패는 소유 상실로 해석하지 않는다. 알 부화 로직의 ETA/활성시간 규칙은 변경하지 않는다.

폰 API는 BaseCampController.load/refreshOwnership/assign/startBuild/startCooking/startTraining/cancel/feedFood/recordVehicle/recordLookOut/tick/performAction을 제공한다. 차량 snapshot은 기존 구독의 입력을 전달받으며 새 FakeVehicleFeed.watch 구독으로 주행을 리셋하지 않는다. profile=demo는 별도 키에 저장한다. 새 UI 연결을 위한 명시적 C API이고 기존 앱 화면을 자동 대체하지 않는다.

`DexStore.allRecords()`는 원본 행의 `sourceEggId`를 잃지 않는 읽기 전용 경계다. 일반 도감 필드는 기존 `DexEntry`로 검증하고, 원본 source ID를 거점 참조에 사용한다. 기존 `all()` 호출과 도감 쓰기는 유지한다.

## 기존 폰 로직 연결

```dart
final camp = BaseCampController(
  store: SharedPreferencesBaseCampStore(profile: 'demo'),
);
await camp.load();
final game = GameController(feed: feed, dex: DexStore(), baseCamp: camp);
// 기존 페어링/알 시작 흐름을 진행한다.
// game의 기존 차량 샘플·창밖 보기·성공한 부화 저장이 camp로 전달된다.

final builders = camp.state.creatures.values.where(
  (c) => CampCatalog.roleFor(c.speciesId) == CampRole.builder,
);
if (builders.isNotEmpty) {
  await camp.assign(CampRole.builder, builders.first.id);
  await camp.startBuild(CampFacility.workshop);
}
// 재료 부족 등 거절은 false와 camp.error로 확인한다.

game.dispose();
camp.dispose(); // 호출부가 공유 camp 인스턴스를 소유한다.
```

위 개체 선택 예시는 builder를 보유한 상태에서 사용한다. 미보유 화면은 가능한 개체가 없는 상태를 안내해야 한다. 실사용 profile은 default, Fake 시연은 demo로 생성한다. 프로필 분리는 거점 저장 범위이며, 기존 도감 자체의 과거 시연 데이터 출처를 소급 구분하지 않는다. 같은 로컬 프로필에는 한 컨트롤러를 사용한다.

건설·요리·훈련을 동시에 하려면 작업자3마리와 훈련 대상1마리 등 중복되지 않는 개체가 필요하다. 훈련 완료 후 `canUseAction`과 `performAction`으로 허용된 행동 ID를 얻고 화면이 해당 연출을 재생한다. C 코드가 실제 동작 이미지·3D 애니메이션까지 제공하는 것은 아니다.

## 검증 기록

2026-11-12 기준 코어77개·폰 전체204개 테스트가 통과했다. 실제 코어와 저장 어댑터를 사용해 병렬 작업, 음식 효과 만료를 가로지르는 오프라인 정산, 재료/환급 중복 방지, 저장 실패, 기존 개체 ID, 기존 차량 구독 연결을 확인했다. 소수 거리 누락·복귀 세대 경쟁·원본 source ID 손실을 재현한 뒤 수정했고 독립 재검토를 받았다.

`dart analyze`는 오류·경고 없이 기존 library 관련 info2건만 남는다. 화면·3D 연출·실제 폰/차량 입력 검증은 이번 C 구현에 포함하지 않았다. 부화 PR #93과 독립된 dev 기반이며, 함께 병합할 때 GameController의 선택 인자와 저장 완료 연결 지점은 양쪽 기능을 보존해 결합한다.
