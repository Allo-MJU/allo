# 폰 가로 게임 화면 설계

## 목표와 현재 상태

폰 게임은 가로 화면으로 제공한다는 사용자 요구를 기준으로 품기·부화·동행을 설계한다. #49 v4의 색·글꼴·모션·터치 크기는 유지하고 세로 레이아웃은 대체한다. 품기·부화·동행 게임 화면의 가로 대응은 구현했다. 도착·도감·연결 등 보조 화면의 전환은 남아 있다.

품기는 왼쪽 알 장면과 오른쪽 상태·고정 조작, 부화는 왼쪽 연출과 오른쪽 설명·고정 진입 버튼으로 배치한다. 동행은 장면 크기를 `CharacterStage.sceneSize`로 전달해 고정 높이를 벗어나며, 장면과 메시지를 분리해 오른쪽 패널에 조작을 고정한다. 게임 화면 진입 시 좌우 가로 방향을 요청하고 마지막 게임 화면 이탈 시 방향 제한을 해제한다. 품기→부화→동행 교체 중에는 공통 방향 관리로 가로 상태를 유지한다. 좁은 창이나 방향 제한을 무시하는 환경에서는 회전 안내와 기존 스크롤 동선을 유지한다.

## 화면 구성

SafeArea 안을 상단 상태 줄과 아래 게임 영역으로 나눈다. 아래 영역은 왼쪽 장면과 오른쪽 조작 패널이다. 기본 게임 동작에는 세로 스크롤이 필요하지 않게 한다.

```text
┌───────────────────────────────────────────────────────┐
│ 알/친구 이름 · 성장/상태                 도감 · 메뉴   │
├─────────────────────────────────────┬─────────────────┤
│                                     │ 반응 메시지     │
│    창문 / 풍경                      │                 │
│     직접 눌러 감싸는 알 / 캐릭터    │ 먹이 / 놀이     │
│                                     │ 노래 / 놀이     │
│                                     │ 창밖 · 봤어!    │
└─────────────────────────────────────┴─────────────────┘
```

- 상단 상태 줄은 도감·메뉴 조작을 포함해 최소 56dp로 설계한다. 주행 종료/도착은 메뉴 안의 보조 동작으로 옮긴다.
- 오른쪽 패널은 가용 너비의 약 28%를 시작점으로 192–256dp 범위에서 잡고, 나머지를 장면에 할당한다. 화면이 넓어져도 버튼 간 이동 거리만 늘리지 않는다.
- 감싸기 버튼은 없으며 알 자체를 직접 눌러 감싼다. 알 터치 영역은 장면에 맞춰 확대하고, 봤어!·노래 영역은 72dp, 일반 조작은 56dp 이상을 유지한다. 낮은 높이에서는 버튼을 2열로 배치한다. 버튼을 축소하거나 장면 위에 겹쳐서 공간을 해결하지 않는다.
- 반응 문구는 조작 패널 위의 고정된 메시지 영역에 표시한다. 긴 문구와 글자 확대는 패널 내부 스크롤로 수용하되, 주 조작 버튼은 고정한다. 오류/연결 상태는 별도 상태 영역에서 알리고 장면 크기가 매번 바뀌지 않게 한다.
- 태블릿·분할 화면처럼 방향 고정을 따르지 않는 환경에서도 실제 LayoutBuilder 제약에 맞춰 배치한다. 최소 게임 영역이 나오지 않는 좁은 세로 창에서는 회전/창 확장 안내와 종료·연결 복구 동작을 제공한다. 게임 시간을 화면 레이아웃 때문에 임의로 정지시키지 않는다.

## 화면별 적용

| 화면 | 장면 | 조작 패널 / 보조 영역 |
| --- | --- | --- |
| 품기 | 직접 눌러 감싸는 알, 성장 연출 | 남은 시간/거리, 성장, 노래, 저장 후 나가기 |
| 부화 | 가로 전체 장면의 중앙에서 기존 2400ms 연출 | 안전영역 내 건너뛰기, 완료 후 동행 시작 |
| 동행 | 창문·캐릭터·의자 | 반응 메시지, 먹이·놀이·봤어!, 횟수는 보조 표시 |
| 도착 | 결과와 캐릭터 | 저장 상태, 도감/다시 시작 |
| 도감 | 가로 그리드 | 상세는 옆 패널 또는 별도 화면 |
| 연결·QR | 가로에서도 입력·스캔 가능한 구조 | 키보드/카메라 권한·오류 안내 보존 |

우선 품기·부화·동행을 전환하고, 도착·도감·연결도 실제 가로 진입에서 누락 없이 검증한다. 연결 화면의 구체적인 패널 배치는 후속 구현 시 입력·카메라 크기에 맞춘다.

## 캐릭터 공간과 제스처

- 창문과 의자는 장면 내부의 비율 기반 앵커로 배치한다. 기기 전체 폭을 기준으로 캐릭터를 이동시키지 않는다. 오른쪽 패널과 노치/시스템 영역에는 진입할 수 없다.
- 캐릭터 크기는 장면의 짧은 변을 기준으로 산정하고 전체 캐릭터와 손 접촉 표현이 경계 안에 들어오도록 제한한다. 창문 붙기·의자 매달리기는 실제 창틀/등받이 위치에서 앵커를 계산한다.
- 현재 구현의 창문 2.4초·재반응 제한 8초, 급변 1.5초, 우선순위·수신 기준선은 그대로 유지한다. 레이아웃 변경으로 차량 사건을 재발생시키지 않는다.
- 드래그는 실제 렌더 위치에서 시작한다. 이동 도중, 화면 크기 변경 중, 급변 발생 중에도 순간 이동·영역 이탈이 없어야 한다. 레이아웃 크기가 바뀌면 진행 중 드래그는 취소하고 새 영역의 기준 위치로 정리한다.
- 모션 감소는 위치 보간·흔들림 없이 최종 위치와 메시지를 제공한다. 배경 패럴랙스는 추가하지 않는다.

## 구현 순서

1. 공통 게임 레이아웃을 만들어 SafeArea, 상태 줄, 장면, 조작 패널을 분리한다. 방향은 좌/우 가로 모두 지원하도록 요청하고 실제 제약 기반 대응도 함께 구현한다.
2. `WindowView`와 `CharacterStage`의 고정 높이를 가용 장면 크기로 대체한다. 장면 앵커와 제스처 경계를 함께 검증한다.
3. 동행 → 품기 → 부화 순서로 레이아웃을 전환한다. GameController·서버 계약·이벤트 타이밍은 유지한다.
4. 도착·도감·연결/QR·키보드와 뒤로 가기를 가로 환경에서 점검한다.
5. character_tour 에뮬레이터로 전체 흐름을 확인하고 PR의 세로 기반 스크린샷/검증 기록을 갱신한다.

## 완료 조건과 검증

- 논리 픽셀 640×360, 844×390, 1024×600에서 정상 게임 화면에 overflow가 없고 주 조작이 스크롤 없이 보인다.
- 좌우 노치/SafeArea, 글자 배율 1.0·1.3·2.0, 모션 감소를 검증한다. 확대 시 메시지는 스크롤 가능하고 버튼 크기와 접근성 순서를 유지한다.
- 캐릭터 터치, 드래그 경계, 애니메이션 중 드래그, 창문/의자 반응, 만료 복귀, resize 중 드래그 취소를 위젯 테스트한다.
- 품기→부화→동행→도착→도감과 세션 종료·앱 복귀 회귀를 통과한다.
- Android 에뮬레이터의 양쪽 가로 방향에서 확인한다. 실제 차량·실기기 검증과 최종 포즈 아트는 별도 미완료 항목으로 남긴다.

## 동행 구현 검증 기록

- `flutter test --no-pub`: 전체 195개 통과. 새 가로 테스트 11개는 3가지 크기 × 3가지 글자 배율(노치 여백 포함), 방향 요청/해제, resize 중 드래그 취소를 검증한다.
- 기존 캐릭터 반응 테스트 11개와 품기→부화→동행→메뉴의 도착→도감 회귀도 통과했다.
- Asta Sans와 실제 시스템 아이콘을 로드한 844×390 및 640×360(글자2.0) 렌더 이미지에서 배치를 확인했다.
- 최소 56dp 먹이/놀이, 72dp 봤어!는 고정하고 설명 영역만 스크롤한다. 도착·Fake 주행 종료는 가로 상단 메뉴에 있다.
- 도착·도감·연결 등 보조 화면 적용, 실기기/실차 검증은 남아 있다.

## 직접 감싸기와 화면 크기 대응

- 별도 감싸기 버튼을 제거했다. 알 터치 또는 스크린리더 누르기 동작은 기존 돌봄 판정을 한 번 호출하고, 900ms 동안 초록 테두리·알 색·안내 문구를 표시한다. 모션 감소에서는 색과 안내를 즉시 표시한다.
- 품기는 가용 높이/폭에 따라 알 크기를 조절한다. 오른쪽의 상태·태그·오류만 스크롤하고 노래·저장 후 나가기는 고정한다. 부화도 연출 크기를 제한하고 설명만 스크롤하며 건너뛰기/동행 시작은 고정한다.
- 기본 글자 크기에서는 주요 게임 정보를 한 화면에 배치한다. 글자를 크게 설정하면 읽을 수 있는 크기를 유지하기 위해 설명 영역의 스크롤을 허용한다. 글자를 강제로 축소하거나 접근성 배율을 무시하지 않는다.
- 640×360, 844×390, 1024×600에서 글자 배율 1.0·1.3·2.0과 노치 여백을 적용해 알 터치·노래·저장·부화 버튼의 노출을 검증한다.

- 품기·부화 확장 후 `flutter test --no-pub`: 전체 215개 통과. `flutter analyze --no-fatal-infos`는 기존 info 2개만 남는다. 640×360 글자1.0/2.0의 품기·부화 렌더 캡처를 확인했다.
